# 47 — кабинет: реальное перекрытие и предупреждение о транспорте

[← оглавление](<README.md>)

[скриншот 47](<../test-results/screenshots/audit/47_account_page_screen.png>)

**наблюдение.** заголовок и «открыть приложение» действительно нарисованы поверх часов/системных значков. форма предупреждает про HTTP и риск перехвата токена; это важное предупреждение уже существует, не требуется изобретать его заново. имя устройства снова «мой пк». нижний текст обещает собственный сервер без SLAG ID, тогда как настройки требуют входа — различие режимов не объяснено.

**изменения.** **p1:** включить кабинет в общий контракт безопасной области и внутренней навигации; дать обычную кнопку возврата в доступной зоне. для рабочего аккаунта требовать защищённый транспорт, тестовый HTTP явно ограничить тестовым режимом; предупреждение не заменяет защиту. **p2:** единый источник имени устройства, понятное «войти по фразе восстановления», объяснение собственного сервера как отдельного режима с условиями, а не противоречащее обещание. секретное поле не должно попадать в аналитику, логи и общие черновики; отключить автокоррекцию/проверку орфографии для seed, поддержать вставку и понятную локальную валидацию.

**приёмка.** на 369 css px заголовок и возврат полностью ниже системных insets. проверить 12/24 слова, лишние пробелы, ошибочную фразу, отказ сети и ожидание подтверждения нового устройства — ошибки без раскрытия секрета. после ухода из формы seed не восстанавливается из общего черновика. надпись «не отправляется на сервер» требует отдельной проверки запросов/реализации; по тексту на экране это обещание, не доказательство. действующую личную seed-фразу для проверки не использовать.
