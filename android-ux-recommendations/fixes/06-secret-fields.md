# 06 — поля ключей: дубль разметки и «умная» клавиатура

[← оглавление](../README.md) · [исходная рекомендация](../06-settings-modal.md)

**до:** [скриншот аудита](<../../test-results/screenshots/audit/06_settings_modal.png>) — два поля ключей были свёрстаны копипастой, оба ходили в один флаг `showKey`, а мобильная клавиатура могла капитализировать первый символ ключа.

**после:** ![после](<shots/06-after.png>)

## что изменено

Добавлен `SecretKeyField` и подключён в двух местах вместо одинаковых блоков. Что он даёт:

- у каждого поля свой флаг видимости, а не общий на всю вкладку;
- `autoCorrect="off"`, `autoCapitalize="none"`, `autoComplete="off"`, `spellCheck={false}` — Android больше не превращает `gsk_` в `Gsk_`;
- кнопка глаза получила `aria-label` («Показать ключ» / «Скрыть ключ») и `aria-pressed`, раньше это была безымянная иконка.

## проверка

- в браузере 375×812: поле ключа переключается `password` → `text`, подпись кнопки меняется.
- `tsc -b`, `oxlint` чистые, состояние `showKey` из `SettingsModal` удалено.

**честно про исходный дефект:** сценарий «открыл один ключ — показался второй» в текущем UI недостижим, поля разных провайдеров показываются по одному (в DOM один `input[type=password]`). То есть дубль был латентным, а не наблюдаемым. Реальная польза правки — дедупликация и отключение автокоррекции.

**десктоп:** поведение то же, атрибуты для автокоррекции там просто игнорируются.
