# 32 / 33 — двойной тап по отправке создавал две записи

[← оглавление](../README.md) · [исходная рекомендация](../33-note-sent.md)

**до:** проверено воспроизведением — два клика по кнопке отправки в одном тике давали **две** записи с одинаковым текстом. В аудите это выглядело как «отправка не сработала», но механика обратная: срабатывала дважды.

## причина

`sendItemWithAttachments` читает `content` из замыкания и очищает состояние только после создания. Оба клика в одном тике видят один и тот же непустой текст и создают по записи.

## что изменено

`Composer`: ref-флаг на время синхронного создания. Второй вызов в том же тике выходит сразу, флаг снимается в `queueMicrotask` — без таймеров и «залипания» кнопки. Пользовательский повтор позже всё равно безопасен: к этому моменту поле уже очищено.

## проверка

- в браузере 375×812: два клика по отправке → **одно** вхождение текста (было два).
- нормальная одиночная отправка работает как раньше.

**честно про устройство:** кадр с планшета телефона для этого пункта не снят — на устройстве текст через автоматизацию в поле не попал, а кнопка отправки в этот момент не отрисована (пустой композер показывает микрофон). Доказательство здесь браузерное и воспроизводимое; на устройстве проверю при следующем заходе в композер.
