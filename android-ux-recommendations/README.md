# android: последовательный разбор и точечные рекомендации

источник: [исходный аудит](<../AUDIT_ANDROID.md>). устройство по данным аудита: HONOR ALI-NX1, android 15, 1200 × 2652 физических px, 369 × 816 css px, dpr 3.25.

## как читается этот документ

каждый кадр — отдельный файл в этой папке, номера совпадают с номерами скриншотов (у 13 и 44 есть буквенные варианты). скриншоты разбирались по одному в порядке числовых имён; вывод по кадру записывался до открытия следующего. код приложения не меняется. это рекомендации, а не отчёт о выполненных исправлениях. общий файл — этот: оглавление, рамки, сверка с аудитом, очередь и регрессия.

- **наблюдение** — то, что действительно видно на изображении.
- **рекомендация** — конкретное изменение; причины в коде не считаются установленными без проверки.
- **приёмка** — сценарий проверки будущего исправления.
- **p1** — мешает основному действию или чтению; **p2** — ухудшает понятность/эргономику; **p3** — косметика. p0 оставляем для подтверждённой потери данных или полной блокировки критического сценария.
- размеры на изображении физические; размер интерактивной области нельзя надёжно установить по размеру нарисованной иконки. целевой минимум для android — 48 × 48 css px при корректном viewport, без пересечения соседних областей. проверять по геометрии элементов и тапами на устройстве.
- скриншот не доказывает работу back, сохранения, синхронизации, анимации, контраст по стандарту или доступное имя элемента. такие выводы требуют отдельной проверки.

## рамки: мобильная эргономика, десктопная психология

сверено с [описанием продукта](<../README.md#L1-L35>) и правилами проекта. основа — не обычный таск-менеджер, а личный поток-монолог с эргономикой telegram и визуальной тишиной linear: быстрый захват мысли, единый композер, три типа одной записи, папки как контекст, раскрытие статьи в фокус-редактор, markdown/local-first. мобильная версия меняет способ управления, не эту модель.

**приоритет этого раздела выше отдельных предложений журнала:**
- нижнее, чатоподобное выравнивание ленты сохраняем; предложение в 16 о старте задач сверху отзывается как обязательная рекомендация. отдельный экран задач может иметь собственное представление, но лента папки не превращается в task dashboard.
- `@`/`#`, командный поиск, аппаратные сочетания и быстрые действия сохраняем. скрываем лишние подсказки при сенсорном вводе, а не возможности десктопа при подключённой клавиатуре.
- в десктопном описании enter отправляет запись. предложение в 26 об enter как переносе строки — только кандидат мобильного контракта, не принятая смена поведения. до решения сохранять существующую семантику; явно различить экранную IME и аппаратную клавиатуру и показать способ переноса строки.
- «таска» присутствует в продуктовом словаре. рекомендации переименовать её в «задачу» означают **согласовать термин во всём продукте**, а не локально переименовать только android. без отдельного решения название типа сохраняется.
- подписи дока, упрощение навигации настроек и альтернативная компоновка — кандидаты, не обязательный редизайн. сначала чинить обрезку, hitbox и выбранное состояние в существующей структуре.
- локальное создание не зависит от аккаунта/сети; SLAG ID нужен конкретному режиму sync. подтверждение создания через ИИ сохраняется, тихая публикация по одной подсказке не вводится.
- единые данные, форматы и пользовательские названия не менять ради мобильной косметики. native-вызовы остаются в model/context, не в UI; рамки, цветные типовые чипы и новые вложенные карточки не добавлять.

все сценарии приёмки ниже **предложены, не выполнены**. код и текущие десктопные сценарии в запущенном приложении в этом проходе не тестировались; сверка философии выполнена по документации, не выдана за desktop smoke-test.

## итоговая очередь изменений

это очередь для будущей реализации, не перечень уже внесённых правок. сначала обязательные исправления существующих сценариев, затем ясность, в конце кандидаты, требующие продуктового решения.

| порядок / приоритет | точечная задача | основание | готово, когда |
|---|---|---|---|
| 1 / p1 | исправить безопасные области кабинета/тостов и геометрию общих шапок | 01, 04–05, 20, 40, 47 | measured insets, без наложений и двойных отступов; portrait/landscape/IME/крупный шрифт |
| 2 / p1 | вернуть кабинет в навигационный стек с сохранением точки входа | 46–50 и прежний тест back | отмена входа/системный back возвращают в настройки; черновик не теряется |
| 3 / p1 | проверить и разделить зоны меню, скрепки и создания | 16–19, 32–36 | независимые 48 × 48 css px, один тап — одно нужное действие, пикер только по прикреплению |
| 4 / p1 | показать папку назначения и обеспечить единый черновик при переходах | 27–33 | тело/тип/папка сохраняются при IME, редакторе, пикере, навигации и рестарте |
| 5 / p1 | явный результат создания и защита от повторной операции | 32–38 | одна запись на действие, ошибка сохраняет черновик, новый ввод не стирается завершением старой операции |
