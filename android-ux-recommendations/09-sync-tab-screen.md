# 09 — синхронизация без входа: противоречивые состояния

[← оглавление](<README.md>)

[скриншот 09](<../test-results/screenshots/audit/09_sync_tab_screen.png>)

**наблюдение.** требование входа объяснено, локальная доступность заметок оговорена — это сохранить. одновременно показаны «1 из 0 устройств», «устройства 1 / 0», «кеш 0 / 0 мб», «полный доступ» и «мгновенно / в реальном времени». телефон назван «мой пк» с ноутбуком. шапка статуса тесная, «это устро…» обрезано, адрес сервера виден лишь частично. две кнопки ведут в кабинет.

**изменения.** **p1:** перед входом показывать единое состояние «заметки сохранены на этом устройстве; синхронизация ждёт входа», не выдавать неизвестный лимит за ноль. локальное устройство отделить от подтверждённых сервером привязок; вместо невозможного отношения — «лимит станет известен после входа». **p2:** один основной переход «войти для синхронизации»; второстепенные параметры свернуть под «дополнительно». имя по умолчанию «этот телефон» и соответствующая иконка, пользовательское имя не перезаписывать. идентификатор отделить от короткой метки «это устройство». серверное поле и кнопку проверки на узком экране расположить вертикально, URL оставить доступным для полного просмотра и копирования.

**приёмка.** без аккаунта, с истёкшей сессией, без сети и с полученным лимитом показываются разные правдивые состояния. «полный доступ» не должен звучать как подтверждение серверной авторизации, если это лишь локальная роль. переключатель «мгновенно» описывает желаемый режим, а не гарантирует android-фон при остановленном процессе; проверить сворачивание/принудительную остановку отдельно. endpoint `http://…` требует отдельной проверки защищённости транспорта: наличие E2EE в подписи не доказывает защиту токенов. по изображению нельзя объявить утечку, но для рабочего сервера рекомендован HTTPS с валидацией сертификата.
