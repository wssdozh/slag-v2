# Аудит Android-приложения SLAG v2 (UX, Верстка, Синхронизация)

**Устройство:** HONOR ALI-NX1 (Android 15, WebView Chrome 156.0.8078.47)  
**Разрешение:** 1200 × 2652 px (CSS: 369 × 816 px, dpr: 3.25)  
**Сборка:** `app-universal-debug.apk` (Tauri v2 + React 19)  
**Метод тестирования:** ADB Shell, Chrome DevTools Protocol (CDP), аппаратные события ввода, инспекция файловой системы `/data/data/com.slag.notes/`.

## 2. Критичные дефекты верстки и Safe Area

### 2.1. Наложение заголовков на системный статус-бар Android
- **Скриншоты:**  
  ![Календарь под статус-баром](test-results/screenshots/audit/04_calendar_view.png)  
  ![Ассистент под статус-баром](test-results/screenshots/audit/05_assistant_tab.png)  
  ![Редактор под статус-баром](test-results/screenshots/audit/20_focus_editor_opened.png)
- **Проблема:** В `MobileCalendarView`, `MobileScreenHeader`, `FullscreenEditor` и `AssistantChat` используется `paddingTop: max(var(--sat), 0px)`. В Android WebView `env(safe-area-inset-top)` возвращает `0px` при дефолтной конфигурации окна, поэтому элементы шапки (кнопки «Назад», «Ноябрь 2026», статус модели ИИ) физически залезают под часы `12:56`, значки Wi-Fi, VoLTE и батареи.
- **Где чинить:** Задать безопасный фолбек `max(var(--sat), 1.75rem)` или централизованно поднять отступ для мобильной платформы.

### 2.2. Наложение системных уведомлений (Toasts) на верхнюю кромку
- **Скриншот:**  
  ![Тосты накладываются на статус-бар](test-results/screenshots/audit/40_after_delete_toast.png)
- **Проблема:** Тост «Запись перемещена в корзину .trash» рендерится с фиксированным `top-2` / `top-4` без учета безопасной зоны. На Android он полностью перекрывается часами и иконками шторки, прочитать текст невозможно.
- **Где чинить:** Добавить в контейнер тостов `padding-top: max(var(--sat), 2.5rem)`.

### 2.3. Полная поломка безопасной зоны в Личном кабинете (AccountCabinet)
- **Скриншот:**  
  ![Личный кабинет под часами](test-results/screenshots/audit/47_account_page_screen.png)
- **Проблема:** Заголовок «Личный кабинет» и кнопка «Открыть приложение» отрисованы в нулевом пикселе экрана прямо поверх системных часов и аккумулятора.

## 3. Дефекты UX и мобильного взаимодействия

### 3.1. Утечка клавиатурных хоткеев в мобильный автокомплит
- **Скриншот:**  
  ![Подсказки клавиш на сенсорном экране](test-results/screenshots/audit/27_folder_autocomplete.png)
- **Проблема:** При вводе `@` (папка) или `#` (тег) во всплывающем меню отображается десктопная подсказка: `↑↓ выбор · Enter применить · Esc отмена`. На смартфоне пользователь нажимает пальцем на экран — десктопные подсказки захламляют компактное меню и вводят в заблуждение.
- **Где чинить:** Скрывать подсказку клавиш при `isMobile` / мобильной платформе.

### 3.2. Кнопка «Открыть в проводнике» в мобильной шторке действий
- **Скриншот:**  
  ![Пункт проводника в меню карточки](test-results/screenshots/audit/19_long_press_card.png)
- **Проблема:** При долгом нажатии на карточку открывается `MobileActionSheet`, в котором есть кнопка «Открыть в проводнике». На Android нативного файлового проводника десктопного типа нет, команда `open_in_folder` в Rust ограничена `#[cfg(desktop)]` — клик по кнопке ничего не делает.
- **Где чинить:** Скрыть кнопку на мобильных устройствах или заменить на «Поделиться» (Web Share API).

### 3.3. Маленький тач-таргет кнопки действий карточки (3 dots)
- **Скриншот:**  
  ![Карточка задачи с подзадачами](test-results/screenshots/audit/16_projects_folder.png)
- **Проблема:** Кнопка действий карточки имеет размер `w-6 h-6` (24 × 24 px). При попытке нажать на нее пальцем пользователь попадает в стрелку сворачивания подзадач или открывает саму запись.
- **Рекомендация:** Увеличить область нажатия до минимального мобильного стандарта 44 × 44 px (`p-2.5` с невидимым хит-боксом).

### 3.4. Соседство скрепки и кнопки отправки в композере
- **Скриншот:**  
  ![Скрепка рядом с отправкой](test-results/screenshots/audit/33_note_sent.png)  
  ![Случайное открытие проводника файлов](test-results/screenshots/audit/34_note_actually_created.png)
- **Проблема:** В правом углу мобильного композера кнопка прикрепления файла `📎` расположена вплотную к кнопке отправки `✈️`. При попытке отправить сообщение палец задевает край скрепки, вызывая нативный Android `PickActivity` (Google DocumentsUI).

### 3.5. Обрезка текста в табах задач (Horizontal Truncation)
- **Скриншот:**  
  ![Обрезка названий табов](test-results/screenshots/audit/03_tasks_tab.png)
- **Проблема:** На экране шириной 369 CSS px кнопки фильтра обрезаются: `К вы... (5)`, `В раб... (1)`.
- **Рекомендация:** Разрешить горизонтальную прокрутку (`overflow-x-auto no-scrollbar`) для мобильного сегментированного контрола.

### 3.6. Дублирование кнопки «Готово» в редакторе
- **Скриншот:**  
  ![Две кнопки Готово](test-results/screenshots/audit/20_focus_editor_opened.png)
- **Проблема:** В полноэкранном редакторе одновременно отображаются две кнопки сохранения: `Готово` в верхней шапке и `✓ Готово` в нижней панели действий.
- **Рекомендация:** Оставить только нижнюю кнопку в панели инструментов, убрав дубль из шапки на мобильном.

## 4. Аудит синхронизации и сетевого слоя

### 4.1. Статус релей-сервера
- Подключение из Android WebView к `http://152.53.199.71:8320/health` проверено через CDP:
  ```json
  {
    "status": "ok",
    "service": "slag-relay",
    "version": "0.2.0",
    "authRequired": true
  }
  ```
  Сетевой доступ есть, HTTP 200 получен за 12 мс.

### 4.2. Идентификация устройства на Android
- **Скриншот:**  
  ![Устройство Мой ПК на телефоне](test-results/screenshots/audit/09_sync_tab_screen.png)
- **Проблема:** По умолчанию в настройках синхронизации устройство генерирует имя `Мой ПК` и отображает пиктограмму ноутбука `[Laptop]`. На Android необходимо подставлять имя модели (`HONOR ALI-NX1` или «Мой телефон») и мобильную пиктограмму `[Smartphone]`.

### 4.3. Блокировка синхронизации без SLAG ID
- На сервере включен режим `authRequired: true`. Все локальные операции сохраняются в очередь `outbox` в `localStorage`:
  ```json
  [
    {"opId": "op_1793787903886_3bzez", "kind": "workspace", "action": "upsert"},
    {"opId": "op_1793787676712_uugbp", "kind": "draft", "action": "upsert"},
    {"opId": "op_1793788453738_h8jv2", "kind": "draft", "action": "delete"}
  ]
  ```
  Пакеты ждут авторизации по seed-фразе в личном кабинете.

### 4.4. Навигация в Личный кабинет ломает аппаратный Back
- **Скриншот:**  
  ![Застревание в ЛК](test-results/screenshots/audit/48_back_from_account.png)
- **Проблема:** Кнопка «Войти в ЛК» вызывает `window.location.search = '?page=account'`. При этом страница аккаунта не добавляет запись в стек навигации LIFO, и нажатие аппаратной кнопки «Назад» на телефоне не возвращает пользователя в приложение. Единственный выход — попасть в микроскопическую кнопку «Открыть приложение» под часами.
- **Где чинить:** Использовать внутренний стейт `navigatePage('account')` вместо перезагрузки страницы через `window.location.search`.

## 5. Что работает отлично (Green Light)

1. **Obsidian Local-First на Android:**
   - Заметки мгновенно сохраняются в нативный каталог приложения `/data/data/com.slag.notes/vaults/main/notes/`.
   - Файлы создаются в чистом формате `.md` с валидным YAML Frontmatter (`id`, `type`, `title`, `created`, `tags`, `folder`).
   - Удаление перемещает файл в `/data/data/com.slag.notes/vaults/main/.trash/` с возможностью восстановления.
2. **Аппаратный LIFO-стек:**
   - Физическая кнопка «Назад» на Android закрывает слои строго в правильном порядке: экранная клавиатура -> всплывающее меню -> модальное окно -> папка -> корень. Приложение не схлопывается случайно.
3. **Ресайз вьюпорта при вводе:**
   - Благодаря `interactive-widget=resizes-content` в `index.html`, при открытии клавиатуры Gboard форма ввода и списки аккуратно поднимаются вверх, курсор не уходит за край экрана.
4. **Интерактивные чекбоксы подзадач:**
   - Подзадачи переключаются тапом прямо из карточки ленты с моментальным зачеркиванием текста.
5. **Нативный файловый диалог:**
   - Скрепка корректно вызывает системный пикер Android `PickActivity` без сбоев рантайма.

## 6. Приоритетный план исправлений

1. **P0 (Блокер верстки):** Добавить безопасный отступ `safe-area-inset-top` (минимум `1.75rem`) во все мобильные заголовки, модалки, тосты и шапку ЛК.
2. **P0 (Навигация):** Перевести переход в ЛК на SPA-роутинг без `window.location.search`, поддержать аппаратный Back на экране аккаунта.
3. **P1 (UX):** Заменить имя устройства на Android на «Мой телефон» / имя вендора, спрятать десктопный пункт «Открыть в проводнике».
4. **P1 (Touch):** Увеличить область нажатия для кнопки `...` карточки (минимум 44 px) и добавить отступ между скрепкой и кнопкой отправки.
5. **P2 (Полировка):** Включить горизонтальный скролл для фильтров статусов задач (`К выполнению`, `В работе`...) и убрать подсказки клавиш `↑↓/Enter/Esc` в мобильном автокомплите.
