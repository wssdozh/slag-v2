# Инструкция: Подключение и использование SLAG MCP

SLAG поставляется с готовым MCP-сервером (Model Context Protocol), позволяющим внешним ИИ-агентам (DeepSeek Harness, Claude Code, Cursor, Goose) управлять хранилищем заметок и задач через стандартный протокол JSON-RPC по stdio.

---

## 1. Сборка бинарника

Перед первым использованием соберите бандл сервера:

```bash
npm run build:mcp
```

Артефакт собирается в `dist/mcp/index.js`.

---

## 2. Подключение к клиентам

### Автоматически (рекомендуется)

```bash
npm run mcp:install
```

Скрипт сам находит хранилище приложения, при отсутствии `dist/mcp/index.js` собирает бандл и
прописывает сервер в Claude Code (`~/.claude.json`), Cursor (`~/.cursor/mcp.json`) и DeepSeek
Harness (`~/.dsh/profiles/web/cordis.patch.yml`). Чужие серверы и остальные настройки в этих
файлах не трогаются, повторный запуск обновляет только нашу запись.

```bash
npm run mcp:install -- --vault "D:\мои заметки"   # другое хранилище
npm run mcp:install -- --clients dsh,cursor       # только нужные клиенты
npm run mcp:install -- --dry-run                  # показать, что будет записано
```

После установки клиент нужно перезапустить: конфиг читается на старте.

### Вручную

### DeepSeek Harness (DSH)
Добавьте секцию в профиль `~/.dsh/profiles/web/cordis.patch.yml`:

```yaml
- insert:
    - id: mcp-slag
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: slag
        transport: stdio
        command: node
        args:
          - /полный/путь/к/slag-v2/dist/mcp/index.js
          - --vault
          - /полный/путь/к/вашему/vault
```

### Claude Code CLI
Выполните команду в терминале:

```bash
claude mcp add slag -- node /полный/путь/к/slag-v2/dist/mcp/index.js --vault /полный/путь/к/вашему/vault
```

Или пропишите в `~/.claude.json`:

```json
{
  "mcpServers": {
    "slag": {
      "command": "node",
      "args": [
        "/полный/путь/к/slag-v2/dist/mcp/index.js",
        "--vault",
        "/полный/путь/к/вашему/vault"
      ]
    }
  }
}
```

### Cursor
Добавьте в `.cursor/mcp.json` (в корне проекта или глобально в `~/.cursor/mcp.json`):

```json
{
  "mcpServers": {
    "slag": {
      "command": "node",
      "args": [
        "/полный/путь/к/slag-v2/dist/mcp/index.js",
        "--vault",
        "/полный/путь/к/вашему/vault"
      ]
    }
  }
}
```

### Goose CLI
В файле `~/.config/goose/config.yaml`:

```yaml
extensions:
  slag:
    name: slag
    cmd: node
    args:
      - /полный/путь/к/slag-v2/dist/mcp/index.js
      - --vault
      - /полный/путь/к/вашему/vault
    type: stdio
```

## 3. Доступные инструменты (Tools)

| Инструмент | Аргументы | Назначение |
|------------|-----------|------------|
| `save_note` | `title`, `content`, `folder`, `type` (`note` \| `task` \| `article`), `tags`, `dueDate`, `priority`, `subtasks`, `id` | Создание или обновление заметки/задачи/статьи. При обновлении по `id` меняются только переданные поля: тип, папка, статус, приоритет и срок остаются прежними, `appendContent` дописывает текст |
| `get_note` | `idOrTitle` | **Полная карточка одним вызовом**: заголовок, тип, папка и её путь, теги, статус, приоритет, срок, даты создания/изменения, чеклист с вложенностью, markdown, связи и список вложений |
| `read_attachment` | `note`, `filename` | Содержимое вложения заметки: текст файла или транскрипт аудио — текстом, картинка — base64 с mime |
| `search_notes` | `query`, `folder`, `type`, `status`, `tag`, `limit` | Полнотекстовый поиск по содержимому и тегам; в строках результата видно число вложений |
| `list_notes` | `folder`, `type`, `tag`, `sortBy`, `limit` | Список заметок с фильтрами; в строке появляется приписка «вложения: N», когда они есть |
| `list_tasks` | `view` (`today` \| `upcoming` \| `overdue` \| `backlog` \| `completed` \| `all`), `folder` | Выборка задач по временным срезам |
| `toggle_task` | `id`, `subtaskId`, `status` (`todo` \| `done`) | Переключение статуса задачи или чекбокса подзадачи |
| `delete_note` | `idOrTitle` | Безопасное перемещение в корзину `.trash/` |
| `list_folders` | — | Дерево папок с описаниями назначения |
| `create_folder`| `path`, `description`, `icon` | Создание новой папки для классификации |
| `list_tags` | — | Частотный словарь существующих тегов |
| `get_vault_stats` | — | Сводная статистика по хранилищу |

### 3.1 Карточка заметки: один вызов вместо трёх

`get_note` (и ресурс `slag://notes/{id}`) возвращает всё сразу. Отдельно за метаданными, телом
или вложениями идти больше не нужно.

Что приходит в карточке:

- **идентификация**: `id`, заголовок, тип (`note` / `task` / `article`), имя файла, путь файла в
  хранилище и абсолютный путь на диске;
- **папка**: путь в хранилище (`Проекты/SLAG`), абсолютный путь папки;
- **поля**: теги, статус, приоритет, срок, напоминание, даты создания и изменения
  (числом и в ISO), закрепление, архив, время чтения и краткое описание для статей;
- **чеклист**: `total` / `done` и пункты с текстом, отметкой и `depth` — вложенность по отступу;
- **связи**: на что отвечает (`replyTo`), с чем связано (`linked`) и кто упоминает её
  (`backlinks`), с заголовками и путями, а не только с id;
- **вложения**: `name`, `type` (`image` / `audio` / `video` / `file`), `mimeType`, `size` и
  `sizeHuman`, `isImage`, `relativePath`, `absolutePath`, `url`, `resourceUri`, `hasBytes`,
  `hasTranscript`;
- **markdown**: файл как он лежит на диске, вместе с frontmatter.

Текстовый ответ карточки — это человекочитаемые секции плюс весь markdown в конце, а
`structuredContent.card` содержит тот же объект для машинного чтения.

### 3.2 Вложения

- `url` — рабочий `file://`-url на десктопе; если байтов на этой машине нет, там лежит
  `slag://attachments/{noteId}/{filename}`.
- `hasBytes: false` значит, что файл приехал из синка и лежит только на другом устройстве.
- `read_attachment` принимает `note` (id, заголовок или имя файла) и `filename` (имя из
  `attachments` или `relativePath`).
  - картинка → элемент `image` с base64 и `mimeType`;
  - текстовый файл → текст;
  - аудио с транскриптом (или OCR-текст файла) → текст, с пометкой «транскрипт»;
  - аудио без транскрипта → пояснение, что текстом отдать нечего.
- Лимиты: текст — 512 КБ, картинки и прочие файлы — 4 МБ. Выше лимита — ошибка с фактическим
  размером и путём на диске, а не обрезанный кусок.

## 4. Ресурсы и шаблоны (Resources)

- `slag://vault/stats` — мгновенный снимок состояния хранилища.
- `slag://vault/tags` — список тегов хранилища.
- `slag://folders` — карта папок с описаниями.
- `slag://tasks/pending` — открытые задачи.
- `slag://note/{id}` — **полная карточка заметки тем же JSON-объектом, что отдаёт `get_note`**
  (включая чеклист, связи и вложения), а не только markdown.
- `slag://attachments/{note}/{filename}` — байты вложения: картинка или файл приходят `blob`-ом с
  mime, текст — текстом. Имя файла в uri кодируется (`encodeURIComponent`), сервер его
  раскодирует; лимиты те же, что у `read_attachment`.

---

## 5. Что изменилось для ботов

- `get_note` больше не «только markdown»: сначала идут метаданные, чеклист, связи и вложения, в
  конце — markdown целиком. Один вызов закрывает и карточку, и тело.
- `slag://notes/{id}` теперь отдаёт `application/json` с карточкой (раньше — `text/markdown`).
- `read_attachment` — новый инструмент для содержимого вложения.
- `list_notes` / `search_notes` / `list_tasks` добавляют ` | вложения: N`, чтобы не ходить наугад.
- `save_note` при обновлении по `id` работает как патч: не переданные поля не сбрасываются.
