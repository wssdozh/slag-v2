## 1. Концепция: переход от фиксированного лейаута к модульной IDE

До сих пор SLAG v2 развивался в рамках классической трёхколоночной структуры:
`[ Левый сайдбар (навигация) | Центр (лента/канбан/календарь) | Правый сайдбар (инфо/ассистент) ]`.

С ростом возможностей системы (агентный ИИ-чат, мульти-представления папок, медиатека, полноэкранный фокус-редактор) пользователю требуется свободная композиция рабочего пространства под конкретную задачу, аналогично **Obsidian, Blender и VS Code**:
* **Глубокий диалог с ИИ:** переместить чат Ассистента в широкую центральную область, а ленту заметок сдвинуть вправо в компактный референс-список.
* **Сравнение и перенос заметок:** разделить рабочую область вертикальным сплитом на две независимые ленты или канбан + редактор статьи.
* **Многомониторный сетап (Pop-out):** «оторвать» окно ИИ-копилота или редактора заметки в отдельное нативное окно операционной системы на второй экран.
* **Фокус-режим:** моментально свернуть второстепенные панели без потери их контекста и вкладок.

## 2. ТРИЗ-анализ композитности интерфейса

### 2.1. Формулировка противоречий
* **Техническое противоречие (ТП):**
  * *Если* мы даем пользователю максимальную свободу перемещения панелей, произвольного сплиттинга и открепления окон, *то* интерфейс покрывает любые экспертные сценарии, *но* сложность состояния стремительно возрастает, а выверенный 95% монохромный минимализм Linear рискует деградировать в перегруженный «пульт управления» с хаосом сплиттеров.
* **Физическое противоречие (ФП):**
  * Сетка интерфейса **должна быть строго зафиксированной и монолитной** (для предсказуемости, скорости 0 мс и чистоты верстки) И **должна быть абсолютно текучей и разборной** (чтобы любой блок мог занять любое место или превратиться в отдельное окно ОС).

### 2.2. Идеальный Конечный Результат (ИКР)
> **Модули сами адаптируют свое представление под габариты предоставленного слота, не требуя от пользователя сложного ручного администрирования окон.** Логика компонента полностью изолирована от его физического контейнера в DOM.

### 2.3. Операторы разрешения по ТРИЗ
1. **Дробление (Принцип №1) + Принцип «Матрёшки» (Принцип №7):**
   * Все функциональные зоны (Лента, Чат ассистента, Дерево папок, Инспектор, Редактор) проектируются как равноправные автономные модули (виджеты). Модуль ничего не знает о том, где он находится — в центре, в боковой вкладке или в отдельном окне.
2. **Фазовый переход / Изменение плотности (Принцип №35):**
   * Ассистент в боковой колонке (ширина < 360px) работает в компактном режиме мессенджера.
   * Тот же ассистент, перемещенный в центр (ширина > 600px), автоматически разворачивает расширенные карточки рассуждений (Reasoning), предпросмотр артефактов и широкие кнопки действий.
3. **Вынесение во второй процесс (Принцип №2) + Разделение в пространстве:**
   * Открепление панели во второе окно ОС не изолирует данные: приложение сохраняет единый рантайм React через DOM-порталы и `/popout.html`.

## 3. Выбор ядра: Dockview (`dockview-react`)

После аудита существующих решений (GoldenLayout, FlexLayout, rc-dock, react-mosaic) в качестве базового движка выбран **`dockview-react`**.

### Почему Dockview:
| Критерий | `dockview-react` | `flexlayout-react` | Самописная сетка |
|---|---|---|---|
| **Зависимости** | **0 зависимостей** | Есть зависимости | 0 зависимостей |
| **Поддержка React 19** | Полная | Ограниченная | Полная |
| **Табы + Сплиты (Тайлинг)** | В коробке (VS Code UX) | В коробке (Bloomberg UX) | Трудоемко |
| **Popout Windows (Окна ОС)** | **Нативная поддержка** | Нативная поддержка | Сложная реализация |
| **Кастомизация под Linear** | 100% чистый CSS vars | Сложные вложенные классы | 100% |
| **Сериализация лейаута** | `toJSON()` / `fromJSON()` | JSON-схема | Требует разработки |

### Стилизация под 95% монохромный контракт SLAG:
`dockview` полностью кастомизируется через переменные темы. Создается фирменная тема `dockview-theme-slag`:
* Базовый фон: `#08090a` (панели) и `#141417` (хедеры вкладок).
* Разделители (Sash/Splitters): 1px монохромный бордер `#27272a`, без толстых полос прокрутки.
* Активная вкладка: чистый текст `#f4f4f5` с нижней линией акцента 1px `#52525b`, без скруглений и «чипсов».
* Неактивная вкладка: приглушенный `#71717a`, подсветка при наведении `#a1a1aa`.
* Никаких градиентов, круглых рамок и радужных индикаторов.

## 4. Архитектура Popout Windows в связке с Tauri v2

Одной из самых сложных задач desktop-приложений является вынос панелей на второй монитор без разрыва состояния.

```text
┌────────────────────────────────────────────────────────────────────────┐
│  ГЛАВНОЕ ОКНО TAURI (WebView2 / Webkit)                                │
│                                                                        │
│  ┌───────────────────────────┐      ┌───────────────────────────────┐  │
│  │ AppContext (React 19)     │      │ Dockview Layout Engine        │  │
│  │ - Хранилище заметок       │ ───► │ - Дерево папок                │  │
│  │ - Orama BM25 Индекс       │      │ - Лента / Канбан              │  │
│  │ - Gemini Streaming State  │      └──────────────┬────────────────┘  │
│  └───────────────────────────┘                     │                   │
│                                           api.addPopoutGroup()         │
└────────────────────────────────────────────────────┼───────────────────┘
                                                     │ window.open('/popout.html')
                                                     ▼
┌────────────────────────────────────────────────────────────────────────┐
│  ДОЧЕРНЕЕ ОКНО ОС (Pop-out Window на 2-м мониторе)                     │
│                                                                        │
│  ┌──────────────────────────────────────────────────────────────────┐  │
│  │ React DOM Portal (React 19 рендерит напрямую в DOM нового окна)  │  │
│  │                                                                  │  │
│  │ 🤖 Модуль Ассистента (AI Chat & Reasoning)                      │  │
│  │ Доступ к общему AppContext без сетевых задержек и IPC-сериализации│  │
│  └──────────────────────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────────────────┘
```

### Принцип работы:
1. В папку `public/` добавляется легковесный шаблон `popout.html`.
2. При вызове действия «Открепить в окно» (`Pop-out`) Dockview вызывает нативный Web API `window.open('/popout.html')`.
3. В среде **Tauri v2** (на базе Windows WebView2) дочернее окно создается как отдельное окно ОС, сохраняя дескриптор `window.opener`.
4. Стили страницы (Tailwind CSS v4 и шрифты Geist) автоматически инжектируются в заголовок нового окна.
5. React-компонент ассистента монтируется в DOM дочернего окна через `ReactDOM.createPortal`.
6. **Результат:** Состояние React не рвется! Стриминг ИИ-ответа продолжается плавно, поиск по заметкам выполняется мгновенно из того же in-memory индекса Orama. При закрытии окна ОС панель автоматически возвращается в сетку основного окна.

## 5. Модульная карта компонентов (First-Class Panels)

Все существующие части интерфейса регистрируются в реестре Dockview как независимые панели:

| Panel ID | Название | Компонент-источник | Описание роли |
|---|---|---|---|
| `sidebar` | Навигация | `<Sidebar />` | Дерево папок, теги, системные режимы Inbox. |
| `feed` | Стрим-лента | `<FeedList />` + `<Composer />` | Хронологический монолог, карточки заметок, быстрый ввод. |
| `kanban` | Канбан-доска | `<KanbanBoard />` | Процессный конвейер задач с доком «Материалы». |
| `calendar` | Календарь | `<CalendarView />` | Временная шкала задач и напоминаний. |
| `assistant` | ИИ-Копилот | `<AssistantChat />` | RAG-чат, Agent Tool Calling, блок рассуждений. |
| `audio` | Аудиоплеер | `<AudioPanel />` | Иммерсивный Now Playing плеер треков и войсов папки с автопереходом. |
| `folder-info` | Инфо папки | `<FolderInfoPanel />` | Описание папки, галерея медиа, аудио, ссылки. |
| `logs` | Логи & HUD | `<LogViewer />` | In-app диагностика, кольцевой буфер событий, FPS и замеры. |
| `moodboard` | Мудборд | `<MoodboardPanel />` | Визуальная бесконечная витрина медиа/скриншотов папки без текста (roadmap). |
| `editor` / `split-editor` | Сплит-редактор | `<FullscreenEditor />` | Полноразмерный редактор статей и документов рядом с лентой (roadmap). |

## 6. Пресеты рабочего пространства (Workspaces)

Вместо того чтобы заставлять пользователя каждый раз вручную собирать сетку, внедряются 4 канонических пресета с переключением через `⌘.` или командное меню:

1. **Default (Канонический триптих):**
   * Лево: Сайдбар (240px).
   * Центр: Стрим / Канбан (flex-1).
   * Право: Табы `[Инфо | Ассистент]` (340px).
2. **AI Lab (Фокус на исследовании и агентах):**
   * Лево: Сайдбар свернут в компактный рейл иконок (48px).
   * Центр: Ассистент на всю ширину (глубокий диалог, рассуждения, генерация заметок).
   * Право: Стрим заметок текущей папки (для сверки фактов).
3. **Deep Focus (Чистое письмо):**
   * Все боковые панели скрыты (0px).
   * В центре: Редактор статьи с центрированной колонкой текста 680px.
4. **Dual Screen (Двухэкранный сетап):**
   * Главный монитор: Сайдбар + Канбан/Лента на весь экран.
   * Второй монитор: Открепленное окно Ассистента с агентами и логами.

Лейаут пользователя автоматически сериализуется при любом изменении в `localStorage` (`slag_workspace_layout_v1`) и восстанавливается при перезапуске приложения.

  - Установка пакета `dockview-react`.
  - Создание базового файла стилей `src/styles/dockview-theme-slag.css` с переменными монохромной палитры.
  - Добавление `public/popout.html` для изоляции открепляемых окон.
- [ ] **Этап 2: Изоляция модулей**
