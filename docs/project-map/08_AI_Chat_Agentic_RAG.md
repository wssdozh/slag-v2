# 💬 ИИ-Чат и Агентный Поиск (Tool Calling + Reasoning)

> Родительский документ: [[00_MOC_Map_of_Content]]  
> Связанные документы: [[03_AI_Engine_Zero_Slop_Gemini]], [[05_Search_Orama_Local_First]], [[07_Roadmap_Implementation]]

## 1. Архитектура решения

Вместо медленного и тяжелого векторного RAG с локальными эмбеддингами используется связка: **LLM с поддержкой вызова инструментов (Function Calling) + локальный поисковый движок Orama (BM25)**.

```
[Пользователь] ➔ "Где таска про сервак с тегом #security?"
       │
       ▼
[LLM (Gemini Flash / Groq / KIE)]
  Генерирует вызов функции:
  search_notes(query: "сервер sync relay", tag: "security", type: "task")
       │
       ▼
[Локальный движок Orama] ➔ отдает 2 точных сниппета за 4 мс
       │
       ▼
[LLM (по необходимости)] ➔ read_note("demo_note_1")
       │
       ▼
[Интерфейс SLAG] ➔ Карточка с цитатой + кликабельный [[Линк на заметку]]
```

## 2. Размещение в интерфейсе (UX) и Области Видимости

В приложении нет отдельного пункта «Ассистент» в левом сайдбаре. Левый сайдбар остается чистым деревом папок.

1. **Размещение в правом сайдбаре (FolderInfoPanel / Copilot)**:
   - Ассистент интегрирован в выдвижную правую панель с переключателем `[ Инфо | Ассистент ]` (горячая клавиша: `⌘J` / `Ctrl+J`).
   - **ТРИЗ-преимущество (Разделение в пространстве)**: центральная область остается сфокусированной на одном из трех рабочих представлений (`[ 📜 Лента | 📋 Канбан | 📅 Календарь ]`), а ИИ работает параллельно в качестве Копилота, отвечая на вопросы и формируя карточки заметок/задач с подтверждением пользователя.
2. **Строгое разграничение контекста**:
   - **Если открыта конкретная папка** (например `Проекты/SLAG v2`):
     - Модель получает системный контекст этой папки и её описание.
     - Инструменты `search_notes` и `read_note` жестко ограничены этой папкой.
     - Ответы строятся исключительно на материалах выбранной папки.
   - **Если открыта системная папка «Входящие»**:
     - Включается режим глобального ассистента: модели доступны **абсолютно все заметки, таски и статьи из всех папок хранилища**.
     - Идеально для вопросов: *«Где я писал про сервак?»*, *«Собери все задачи с дедлайном на завтра по всем проектам»*.
3. **Управление Reasoning (Рассуждениями)**:
   - В поле ввода чата размещен селектор глубины мышления:
     `[ 🧠 Reasoning: Выкл | Low | Med | High ]`.
   - Для моделей с цепочкой рассуждений (DeepSeek R1 через Groq/KIE, Gemini 2.0 Flash Thinking) регулирует лимит токенов на рассуждения (budget tokens).
   - Блок мыслей скрыт под кликабельным аккордеоном `Рассуждения (1.2 сек) ↓`.
4. **Тумблер внешнего поиска**:
   - `[ 🌐 Сеть: Вкл / Выкл ]` — подключение Google Search / Web API для гибридных запросов.

## 3. Спецификация инструментов модели (Tool Calling Schema)

Модели передаются 4 строгих инструмента:

### 3.1. `search_notes` (Поиск по содержимому и метаданным)
Выполняет нечеткий полнотекстовый поиск через локальный Orama BM25.
```typescript
interface SearchNotesParams {
  query: string;        // Поисковая фраза с учетом синонимов
  folder?: string;     // Ограничение по папке (например "Проекты")
  tag?: string;        // Фильтр по точному тегу (например "security")
  type?: 'note' | 'task' | 'article'; // Фильтр по типу записи
  status?: 'todo' | 'done';           // Фильтр статуса задачи
}
```

### 3.2. `read_note` (Чтение полного файла)
Вызывается, если сниппета из поиска недостаточно для ответа.
```typescript
interface ReadNoteParams {
  id: string; // Идентификатор заметки
}
// Возвращает: чистый текст Markdown с YAML Frontmatter
```

### 3.3. `get_vault_stats` (Статистика по тегам и папкам)
Позволяет модели мгновенно отвечать на вопросы о количестве заметок, списках активных тем и распределении файлов.
```typescript
interface GetVaultStatsParams {
  target: 'tags' | 'folders' | 'all';
}
// Возвращает:
// {
//   tags: { "дизайн": 12, "архитектура": 5, "безопасность": 2 },
//   folders: { "Входящие": 4, "Проекты/SLAG v2": 18, "Личное": 7 },
//   totalNotes: 29
// }
```

### 3.4. `web_search` (Поиск в сети)
Доступен модели только если пользователь включил тумблер `[ 🌐 Сеть ]`.
```typescript
interface WebSearchParams {
  query: string;
}
```

## 4. Контракт безопасности и подтверждение действий

Модель полностью изолирована от разрушительных операций с диском:

1. **Автономные операции (Read-Only)**:
   - `search_notes`, `read_note`, `get_vault_stats`, `web_search`. Выполняются без подтверждения.
2. **Создание заметки по итогам диалога**:
   - Модель не пишет файл втихую. Она возвращает специальный блок `action: create_note`.
   - В чате рендерится карточка-черновик:
     `Заголовок: Резюме встречи | Папка: Проекты/SLAG v2 | Теги: #meeting`
     Кнопка: `[ 💾 Создать заметку ]`. Файл сохраняется только по клику человека.
3. **Редактирование существующей заметки**:
   - Модель возвращает блок `action: patch_note`.
   - Отображается всплывающее окно сравнения версий (Diff view). Изменения вступают в силу после клика `[Применить правки]`.
4. **Удаление файлов**:
   - **Запрещено на уровне кода API**. Функция удаления файлов в инструментарий модели не передается.

## 5. Поддерживаемые провайдеры и API

В настройках (`SettingsModal` ➔ раздел «ИИ & Провайдеры») пользователь выбирает рабочий бэкенд:

1. **Google Gemini API**:
   - Модели: `gemini-2.0-flash`, `gemini-2.0-flash-thinking-exp`.
   - Плюсы: встроенный Google Search, бесплатные квоты, задержка < 400 мс.
2. **Groq API**:
   - Модели: `openai/gpt-oss-120b` (500+ токенов/сек, контекст 128K, поддержка Tool Calling и рассуждений), `llama-3.3-70b-versatile`, `deepseek-r1-distill-llama-70b`.
   - Плюсы: сверхвысокая скорость генерации, аппаратные LPU, OpenAI-совместимый API с поддержкой структурированного JSON и Function Calling.
3. **KIE / OpenRouter / Локальные OpenAI-совместимые эндпоинты**:
   - Подключение любого совместимого сервиса с поддержкой JSON-mode и Tool Calling.
