## 1. Философия Zero-Slop (Тихий ИИ)

В большинстве современных продуктов внедрение ИИ превращается в визуальный шум: чат-боты в углу экрана, анимации «ИИ думает...», громоздкие предисловия («Здравствуйте! Я проанализировал ваш текст и вот что нашел...»).

**В SLAG v2 ИИ строго утилитарен и молчалив:**
- ИИ никогда не здоровается, не извиняется и не пишет вступительных предложений.
- Запросы отправляются в высокоскоростные модели:
  - **Groq LPU**: модель `openai/gpt-oss-120b` (скорость более 500 токенов/сек, контекст 128K, аппаратная поддержка вызова функций и рассуждений) или `llama-3.3-70b-versatile`.
  - **Google Gemini**: модель `gemini-2.0-flash` со строгим контрактом `responseMimeType: "application/json"`.
  - **Подписка (SLAG Relay AI Gateway)**: `deepseek-v4-1-flash` через `POST {relay}/api/ai/chat`; шлюз проксирует KIE `/openai/v1/responses`, потому что chat-completions у KIE не обслуживает эти модели. Тариф `fast/smart/deep` выбирает только усилие рассуждения (`none/low/high`), модель одна — чужие шлюз режет (`400 model_not_allowed`).
- Ответы отдаются строго в формате JSON или через контракты Tool Calling.
- Время ответа на классификацию составляет менее 200–400 мс.
- Если у пользователя нет API-ключа или отсутствует подключение к сети, приложение работает бесшовно благодаря встроенной локальной эвристике и Orama BM25.

## 2. Предварительная индексация таксономии и норма тегирования

Главная проблема систем авто-тегирования — бесконтрольное появление дубликатов и близких синонимов (`#фронтенд`, `#frontend`, `#верстка`, `#UI`). 

В SLAG v2 действует **строгая норма таксономии (Tag Taxonomy Norm)**:

### 2.1. Стандарт оформления тегов
1. **Синтаксис**: только строчные буквы (`lowercase` или `kebab-case`), без символа `#`, без пробелов, разделитель составных слов — дефис `-` (например: `дизайн`, `react-hooks`, `e2e-тесты`).
2. **Бюджет плотности**: строго от 1 до 3 тегов на запись (максимум 4 для лонгридов).
3. **Приоритет существующего словаря (Anti-Duplication)**:
   - Перед каждым вызовом модели из хранилища извлекается полный актуальный словарь тегов (`storage.getAllExistingTags()`).
   - Если смысл заметки пересекается с существующим тегом более чем на 70%, модель **обязана использовать существующий тег**.
   - Запрещено создавать синонимы (если есть `дизайн`, запрещены `ui`, `интерфейс`, `design`).
4. **Условие создания нового тега**:
   - Новый тег генерируется **ТОЛЬКО** если тема фундаментально отсутствует в словаре и в настройках включен параметр `allowNewTags: true`.
   - Не более одного нового тега за вызов.

```
[1. Индексация хранилища]
  Сбор всех уникальных тегов пользователя:
  ['дизайн', 'архитектура', 'react', 'tauri', 'финансы']
             │
             ▼
[2. Формирование Zero-Slop промпта]
  Передача словаря и лимитов в Groq / Gemini:
  "Используй теги из словаря. Новый тег создавай
   ТОЛЬКО при принципиально новой теме!"
             │
             ▼
[3. Валидированный JSON результат]
  ["дизайн", "react"]
```

### 2.2. Настройки таксономии в приложении (`SettingsModal`)
- **Максимум тегов на заметку**: настраиваемый диапазон `1..5` (по умолчанию `3`).
- **Разрешить создание новых тегов**: тумблер `Вкл / Выкл` (при выключении действует жесткий белый список — модель выбирает строго из уже существующих тегов).
- **Стиль регистра**: `lowercase` (`дизайн`) / `kebab-case` (`ui-ux`).
- **Пользовательские правила тегирования**: поле ввода для кастомных инструкций классификации.

## 3. Краткая норма для автономных агентов (Agent Codex)

Каждый агент, взаимодействующий с заметками и метаданными, подчиняется своду правил:
1. **ZERO-SLOP**: Никаких приветствий, преамбул и вежливых концовок. Либо чистый JSON, либо вызов инструмента, либо прямой фактологический ответ.
2. **TAXONOMY FIRST**: Всегда проверять существующие теги хранилища перед предложением новых. Дубликаты и синонимы запрещены.
3. **SCOPE DISCIPLINE**: В папке контекст строго ограничен папкой. Во «Входящих» — доступ ко всей базе.
4. **GROUNDING VIA TOOLS**: Не выдумывать содержание заметок. При любых вопросах о фактах вызывать `search_notes` / `read_note`. Ссылки оформлять как `[[Заметка]]`.
5. **READ-ONLY SAFETY**: Модель не изменяет файлы напрямую. Создание заметки оформляется через блок `action: create_note` и карточку подтверждения в UI.
6. **REASONING ISOLATION**: Мысли и цепочки рассуждений выводятся в отдельный блок reasoning и скрываются под аккордеон `[ 🧠 Рассуждения (XXs) ]`.

## 4. Интеллектуальный AI Triage папки «Входящие»

Папка «Входящие» служит точкой сброса мыслей. Когда в ней накапливаются заметки, пользователь нажимает кнопку **«ИИ-сортировка»** в шапке ленты.

### 4.1. Механика работы триажа
1. Приложение считывает неразобранные заметки из папки `Входящие`.
2. Из `.slag/folders.json` загружаются описания тематических папок (например: *«Проекты/SLAG v2: Разработка приложения заметок в стиле Linear на React и Tauri v2»*).
3. Groq (`openai/gpt-oss-120b`) или Gemini Flash получают контекст заметок и описания папок, после чего возвращают план распределения:
   ```json
   [
     {
       "itemId": "note_123",
       "suggestedFolder": "Проекты/SLAG v2",
       "confidence": 0.94,
       "reason": "Заметка содержит детали реализации архитектуры композера."
     }
   ]
   ```
4. **Модальное окно подтверждения (Triage Modal)**:
   - Пользователь видит прозрачный список карточек с предложенными папками и причинами.
   - Пользователь может скорректировать назначение любой заметки или снять выбор.
   - По нажатию «Применить всё» файлы на диске безопасно перемещаются в папки назначения.

## 5. Оффлайн-фолбэк (Локальная эвристика)

Если в настройках не указаны API-ключи Groq/Gemini или устройство находится в режиме полета:
- При вводе хэштегов прямо в тексте (`#идея`, `#баг`) они мгновенно извлекаются регулярным выражением `/#([a-zA-Zа-яА-Я0-9_-]+)/g`.
- При нажатии `+Ai` запускается локальный статистический анализатор TF-IDF по заголовку и первым строкам, который подбирает наиболее подходящие существующие теги из локального словаря за 5 миллисекунд.
- Ассистент в оффлайне использует локальный BM25-поиск Orama и словарь тегов хранилища.
