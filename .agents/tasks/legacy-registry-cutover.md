# Разобрать старую очередь при запуске реестра

- **цель**: запустить реестр при старых правках заметок и черновиков, сохранив неподтверждённые отличия для сравнения.
- **трогаем**: запуск синхронизации, старую очередь, журнал и диалог конфликтов, регрессионные тесты.
- **не трогаем**: релей и его БД, действующие хранилища устройств и их настройки, историческую ошибку state.json на Windows.
- **готово когда**: регрессии подтверждают сохранность правок, отсутствие автоматической отправки и возможность синхронизации других записей; сборка и проверки проходят.
- **уже выяснили**: на ноутбуке блокируют одна операция item/upsert и один draft/upsert; у них нет доказанной базы. Перенос должен переживать разрыв между двумя дисковыми записями.

---

- **итог**: сессия принимает локальные правки до подтверждения релея, но начинает загрузку только после записи альтернатив и подтверждённого сброса старой очереди. Отложенные записи черновиков нужно было сбрасывать перед переносом; для браузерной очереди потребовалось отдельно дождаться записи prefs.
- **проверка**: `npm run check`, `npm run build`, 296 скриптовых тестов и 9 целевых Playwright прошли в копии с тем же патчем поверх базы до `fbc48ea3`; один нативный Playwright уже помечен `skip`. На текущей ветке `fbc48ea3` приносит семь прежних ошибок TypeScript в незавершённом восстановлении хранилищ; проверено на чистом HEAD. Этот коммит не менялся.
- **осталось**: выпуск и установка исправленной сборки, затем проверка реальной очереди на ноутбуке. Записи вне поддержанных типов не переносятся автоматически.
