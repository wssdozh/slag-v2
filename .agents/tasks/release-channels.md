# релизные каналы и ci/cd на github

## цель

собирать и публиковать релизы из github actions по тегам и пушу в `master`, а не руками
через `publish-release.ps1`; в клиенте дать выбор канала `release` / `beta` / `dev`, и описать
правила версионности так, чтобы по ним можно было жить без устных договорённостей.

## что трогаем

- `.github/workflows/release.yml` — переезд на `push: tags v*`, `push: branches master` (dev) и
  ручной запуск; метаданные релиза считает `scripts/release-meta.mjs`.
- `.github/workflows/ci.yml` — мелкая унификация установки pnpm, поведение то же.
- `scripts/release-meta.mjs` — единственное место, где живёт правило «ref → версия, канал, тег,
  prerelease». его же гоняет ручной запуск воркфлоу, он же покрыт `node --test`.
- `scripts/release.mjs` — подпись артефактов, `latest.json`, публикация через `gh release`.
  заменяет `scripts/publish-release.ps1`.
- `src-tauri/src/updater.rs` — `Channel`, адрес манифеста на канал, команды принимают канал.
- `src/lib/platform/appUpdate.ts`, `src/context/hooks/useAppUpdates.ts`,
  `src/components/Settings/UpdatesSettingsTab.tsx`, `src/types/index.ts`, `src/config` — выбор
  канала, хранение в `localStorage['slag:update-channel']`, строка в настройках.
- `docs/RELEASING.md` — правила версий, каналов, versionCode и откатов.

## чего не трогаем

- `tauri-plugin-updater` не подключаем: своя механика (sha256 + minisign) остаётся.
- linux себя не обновляет — как и было, канал влияет только на показ версии.
- формат `latest.json` не меняется: старый клиент продолжает читать `latest`.

## критерий готовности

- `npm run check` — 0 warnings / 0 errors, `cargo check` в `src-tauri` — чисто.
- `node --test scripts/release-meta.test.mjs` — зелёный (правила каналов).
- в настройках видна строка канала, переключение меняет адрес манифеста, e2e на это зелёный.
- тег `v1.2.3` даёт обычный релиз, `v1.2.3-beta.1` и пуш в master — prerelease в свой канал.

## как оказалось на самом деле

- `scripts/publish-release.ps1` пришлось выкинуть целиком, а не обернуть: он бампал версию и
  собирал сам, то есть дублировал бы воркфлоу. вместо него `scripts/release.mjs` (подпись +
  манифест + `gh release`) и `scripts/release-meta.mjs` (правила ref → версия/канал/тег).
- android-костыль с `versionCode` вылез в правило: предрелиз режется от **следующего** патча,
  иначе `1.2.4-dev.x` и `1.2.4` дают одинаковый `versionCode` и система отказывает в апгрейде.
  поэтому версия в `tauri.conf.json` теперь «всегда следующая нерелизнутая».
- сборка версии для предрелиза делается через `--config <json>` с `{"version": ...}`: править
  `Cargo.toml`/`tauri.conf.json` в CI нельзя, иначе следующий коммит приезжает с чужой версией.
- канал уехал в `localStorage`, а не в синкаемый конфиг: телефон и ноут спокойно живут на разных
  каналах, и переключение одного не ломает другой.
- переключение канала сбрасывает найденный оффер: иначе версия из `dev` осталась бы на кнопке
  «установить», пока клиент уже читает `release`.
- e2e поймал собственную же ловушку: `addInitScript` чистит `localStorage` на **каждой**
  навигации, поэтому тест «канал пережил перезагрузку» проверял сам себя. убрал init-script.

## дубли позиций на странице релизов (после первого прогона)

- на каждый канал приходится **две** позиции: сборка `v<версия>` (файлы + манифест) и тег канала `dev`/`beta`
  (только `latest.json`, перезаписывается). схлопнуть в одну нельзя: клиенту нужен неподвижный URL манифеста.
  поэтому развели их по заголовкам и телам через `scripts/release-text.mjs`: `SLAG <версия>` и `канал <канал>`.
- права на текст релиза — у скрипта, не у человека: `buildReleaseBody` / `channelReleaseBody`.
- три запрета на повтор: тот же тег = те же sha256 (иначе падение), канал не едет вниз по semver (`--force`
  на осознанный откат), стабильный тег не перезаписывается вообще.
- грабли прогона: первый `release:dev` прицепился к зависшему в очереди рану и опубликовал `dev.7` **до**
  коммита с шаблоном, поэтому на странице ещё жили старые заголовки. лечится новым прогоном с HEAD — `dev.8`
  уже с шаблоном, старые записи переименованы `gh release edit`.
