# лендинг slag: довести публичную страницу до правды и вынести на домен

- **цель**: человек по ссылке за 10 секунд понимает, что такое slag, скачивает рабочий файл, а банк/платёжка видит на сайте политику, соглашение, тарифы и контакт поддержки
- **трогаем**: `src/components/Landing/**`, новый `site/` (статика), `docs/` (публикация), телеметрия лендинга (`relay` уже умеет `POST /api/telemetry/event`)
- **не трогаем**: `src-tauri/**`, `relay/**` кроме чтения, движок синка
- **готово когда**: домен открывается без `?page=landing`; кнопка скачивания качает реальный артефакт; версия и цены совпадают с `package.json` и `relay/settings.py`; есть `/privacy`, `/terms`, `/releases`, `/docs`; `npm run check` + `npm run build` зелёные
- **уже выяснили**: лендинг уже существует, см. аудит ниже
- **где что теперь**: релей (`relay/**` — вместе с телеметрией, тарифами и будущими тикетами) переехал в отдельный репо `wssdozh/slag-relay`. ссылки на `relay/*` в этом файле исторические; срезы 4–5 делаются там, здесь остаётся клиент и `?page=landing`

## 1. гипотеза

если на своём домене появится страница, которая честно объясняет local-first, показывает живые скрины приложения и даёт рабочий `.exe`/`.apk`, то доля визитов, доходящих до скачивания, будет ≥ 25%, и за две недели после выката наберётся ≥ 100 визитов и ≥ 20 скачиваний.

мерим: `telemetry_event` с `eventType` = `landing_view` → `cta_click` → `download_start`, смотрим в админке (сейчас воронка рисуется из воздуха, см. п.3.9).

## 3. аудит своего кода

`docs/CODE_MAP.md` → `src/App.tsx:223` → `src/components/Landing/LandingPage.tsx` (472 строки).

1. страница уже есть и живёт по `?page=landing` внутри той же SPA-сборки, а не по адресу домена: корень сайта грузит всё приложение, ссылку не отправить в чат, SEO нулевое.
2. кнопка «Скачать .exe» — заглушка: `link.href = '#'` и таймер на 3 секунды (`LandingPage.tsx:22-30`). реального файла нет.
3. версия в шапке захардкожена `v0.1.0`, в `package.json` — `0.2.4`. сайт врёт первым же бейджем.
4. цены врут: на странице `Smile 199 ₽` / `Angry 499 ₽`, в релее MRR считается как 190/490 (`relay/routes_admin.py:119`). лимиты устройств и кеша совпадают с `relay/settings.py:112`.
5. скриншотов нет — вместо них окно приложения, нарисованное `div`-ами. в репо при этом лежат живые скрины: `screenshots/`, `docs/screenshots/`, `docs/comparison/`.
6. цифры-выдумки: «1.2 мс Orama», «~40 мс Obsidian», «~800 мс Notion», «< 20 мс», «17 МБ», «10 000 заметок», «SAS 6 цифр». бренд-гайд сам запрещает промо-пафос, а тут ещё и сравнение с конкурентами без источника.
7. юридики нет: ни `/privacy`, ни `/terms`, ни цен с описанием оплаты, ни контакта поддержки. для эквайринга (Platega → банк) это ровно тот набор, который просят в первом же сообщении.
8. документации как сайта нет: 24 `.md` в `docs/` и 15 в `docs/project-map/`, но без навигации и без оглавления под публикацию.
9. аналитика — фикция: `relay/routes_admin_ops.py:241-257` при отсутствии событий считает `landing_views = paid_count * 20 + 25`, `paywall_views = paid_count * 4 + 6`, `checkout_starts = paid_count * 2 + 2`. клиент при этом не шлёт ни одного `landing_view`/`cta_click`. эндпоинт `POST /api/telemetry/event` есть и работает (`relay/routes_auth.py:29`).
10. тесты/инфраструктура: `.github/` нет вообще, публикация сайта не автоматизирована; релизы уже собираются `scripts/publish-release.ps1` в GitHub releases репозитория `wssdozh/slag-v2`.

## 4. ux-путь

сейчас: ссылка в чате → GitHub → README (146 строк) → Releases → найти `.exe` → скачать. 5 шагов, половина на английском и на гите.

после: домен → заголовок и один CTA → файл качается. 2 шага. дальше по желанию: скрины, тарифы, `/docs`, `/releases`, поддержка.

где затупит: (а) «скачать» нажимают на телефоне, а там `.exe` — нужен явный выбор платформы или редирект на apk; (б) «199 ₽» vs кабинет с 190 ₽ — вопрос доверия; (в) тикет-система в первом срезе не нужна, но кнопка «поддержка» должна вести куда-то живое.

## 5. вердикт

**делаем урезанно**: не новый лендинг с нуля, а вынос существующего в статику на домен + доведение до правды (версия, цены, реальные файлы и скрины, убрать выдуманные цифры) + юридический минимум из трёх страниц + `/releases` + `/docs` из существующих `.md`. публичный трекер и A/B — следующим срезом, там нужна аудитория, которой пока нет.

## 6. решения (подтверждены)

- сайт — **отдельный репозиторий**, кода сайта в репо приложения нет; в приложении остаётся тонкая страница-переходник `?page=landing` → редирект на домен
- читатель — **оба**: первый экран простой («записал мысль за секунду, файлы мои»), ниже технический блок (markdown, E2EE релей, Orama, MCP)
- оплата — **тарифы и кнопка с заглушкой** («оплата пока недоступна»), как требует банк
- саппорт — **сразу публичный трекер с приватными тикетами**, приватность режется на сервере, не в CSS

## 7. план по срезам

1. **правда в приложении**: версия шапки из `latest.json` (а не `v0.1.0`), цена и лимиты из `relay/settings.py` (`price_rub` рядом с `label`), кнопка скачивания ведёт на `releases/latest/download/…`, нарисованный мок окна → реальные скрины из `docs/screenshots/`. выдуманные «1.2 мс» и «~40 мс Obsidian» убрать.
2. **site-репо** `slag-site`: Astro + Starlight. `/` лендинг, `/docs` (24 `.md` из `docs/`, чистим внутреннее), `/releases` (GitHub API + `latest.json`), `/privacy`, `/terms`, `/support`.
3. **деплой**: домен + TLS; сборка сайта кладётся на netcup рядом с релеем (`SLAG_STATIC_DIR` уже умеет отдавать статику, `relay/routes_static.py`). приложение — на поддомене.
4. **метрики**: сайт шлёт `landing_view` → `cta_click` → `download_start` в `POST /api/telemetry/event`; в `relay/routes_admin_ops.py` убрать синтетику `landing_views = paid_count * 20 + 25`.
5. **трекер** (отдельная фича, в релее): таблица `tickets` + `ticket_messages`, анонимный токен автора в cookie, `visibility` (`public`/`private`), список отдаёт только `public`, приватный открывается токеном автора или админом; UI на сайте; антиспам по `RATE_LIMIT_*`.
