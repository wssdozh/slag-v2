# Повторный стресс-прогон восстановления синхронизации

- **цель**: несколько повреждённых файлов за один сбой; точное восстановление или безопасная остановка без потери заметок и без лишних действий в интерфейсе.
- **трогаем**: тесты Rust, Playwright и loopback-релея, загрузку барьера проекции при повреждённой привязке, фоновое наблюдение за файлами, документацию покрытия.
- **не трогаем**: рабочие хранилища, рабочий релей, установленные приложения, алгоритмы слияния.
- **готово когда**: перемешанные повреждения воспроизводятся по seed, прерванный коммит не читается как новый, повтор сохранения работает после снятия ошибки, барьер уже начатого переноса действует и в локальном режиме; проходят проверки ветки.
- **уже выяснили**: прежняя матрица применяет один вид отказа к каждому файлу отдельно; браузерные тесты прежде выбирали один потерянный файл.

## Результат

- В браузере составной сбой был красным: видны все 106 заметок вместо 105, включая промежуточную копию незавершённого переноса. Причина — ошибка чтения конфигурации отбрасывала успешное чтение отдельного журнала. Теперь доступный проверенный журнал сохраняет барьер при открытии и на следующем проходе watcher; строгий режим для синка по-прежнему требует обе части. Остальная локальная работа и повторное открытие после сохранения проходят, сеть не открывается, очередь неизвестна, не ноль.
- Вторая красная проба выдала ложное удаление и повторное появление файла после нескольких отказов `stat`. Теперь отрицательное подтверждение отличается от временной ошибки чтения. Отказ чтения вложенной папки также оставляет её последнее состояние, реальная правка в соседней ветке проходит; настоящее удаление по-прежнему подтверждается после двух проходов.
- Нативный Windows-прогон: 10 тестов. Помимо 72 старых проверок, 64 составных сценария (192 проверки отдельных поколений: 79 дали точные данные, 113 остановились без перезаписи) и управляемый `StorageFull` на втором слоте до публикации маркера. При наличии старого поколения повтор успешен; на первом коммите сиротский слот не выдаётся за пустую очередь. Отдельный повтор `267`: одно поколение прочиталось, два остановились. Изменения выполняются только внутри временных каталогов.
- Реальный Python-релей `06e6be7`, loopback, временная SQLite, 40 мс искусственного RTT: обычный режим и `--offline` прошли. В новом сценарии очистка истории между страницами сдвинула `floor` с `159` до `161`; три клиента сошлись на `162`, одно локальное создание ушло ровно раз, существующие альтернативы не поменялись. Проверены логические проекции тестовых клиентов, не физические файлы установленных устройств.
- `npm run check` (0 ошибок и предупреждений), `npm run build`, 337 скриптовых и 15 целевых браузерных тестов прошли. Включена старая проверка холодной гидратации: её IPC-подмена теперь читает защищённое поколение, а пять секций настроек читают один общий снимок.

Не проверяли реальное отключение питания, полную потерю носителя, физический диск Linux/Android или повреждения в живом профиле. Повторный сбой может оставить синхронизацию на паузе; если нет подтверждающих байтов, автоматически угадывать очередь нельзя.
