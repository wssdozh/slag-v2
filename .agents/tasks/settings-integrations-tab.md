# настройки: «интеграции» отдельно от «уведомлений»

- **цель**: telegram-канал и права бота живут в своей вкладке `интеграции`; вкладка `уведомления` — про системные уведомления этого устройства (о чём и когда беспокоить) и умеет показать тестовый тост.
- **трогаем**: `src/config/settingsTabs.ts`, `src/components/Modals/SettingsModal.tsx`, `src/components/Settings/IntegrationsSettingsTab.tsx` (новый), `src/components/Settings/NotificationsSettingsTab.tsx`, `src/components/Settings/notifications/ContentGroup.tsx`, `src/components/Settings/notifications/SystemGroup.tsx` (новый), `src/lib/notify/plan.ts`, `e2e/settings_integrations.spec.ts` (новый), одна строка в `docs/project-map/14_Module_Layout.md`.
- **не трогаем**: хранилище (`NotifyPrefs`/`NotifyRoute`), `src/lib/notify/assistant.ts`, `src/lib/notify/assistantAction.ts`, `relay/**`, `src/components/Mobile/MobileSettingsView.tsx`, `e2e/settings_consistency.spec.ts`, файлы групп `ChannelGroup.tsx` / `AssistantGroup.tsx` (не переезжают из `notifications/`).
- **готово когда**: `npm run check` (две строки, ноль warnings), `npm run build`, `npx playwright test e2e/settings_integrations.spec.ts` зелёный; в `интеграциях` видны канал + спойлер + ладдер, в `уведомлениях` ноль строк со словом telegram; скриншоты `test-results/screenshots/settings-integrations-1280.png` и `settings-notifications-1280.png` сняты.
- **уже выяснили**:
  - `SETTINGS_TABS` — единственная точка регистрации; мобильный список настроек рисуется по ней же, поэтому новая вкладка появляется сама;
  - `sed`-правка не нужна: `tabPane` рендерится с `key={activeTab}`, две вкладки одновременно не живут, значит оба таба могут независимо читать `getNotifyPrefs()`/`getNotifyRoutes()` при монтировании без гонки записи;
  - системный тост уже есть — `showLocalReminder` в `plan.ts` через `@tauri-apps/plugin-notification`, но молчит при активном telegram-маршруте; тест-кнопке нужен отдельный вход `sendLocalNotification`;
  - рабочее дерево грязное от параллельной сессии (апдейтер): `settingsTabs.ts`, `SettingsModal.tsx`, `e2e/settings_consistency.spec.ts`. правим точечными `edit`, чужой спек не трогаем, перед коммитом сверяем `git status`.

оказалось не так:
- отдавать наружу сам `@tauri-apps/plugin-notification` из компонента нельзя (инвариант: tauri только в `src/lib/*`), поэтому тест-кнопка получает не промис плагина, а строку `'sent' | 'denied' | 'unsupported'` — по ней и выбирается тост. заодно `showLocalReminder` перестал держать свою копию разрешений.
- описание системного тоста не может произносить слово telegram: e2e прямо проверяет, что на вкладке «Уведомления» его нет. текст стал «всплывают, только пока канал доставки не подключён».
- `SettingsDivider` в `ContentGroup` пришлось вернуть: он разделяет два свича, а не только уехавшие строки — первая попытка «убрать неиспользуемый импорт» уронила tsc.
- `settingsTabs.ts` и `SettingsModal.tsx` нельзя коммитить отдельно от чужой работы: в одной строке импорта и в union-типе живут и `Plug` (мой), и апдейтер параллельной сессии. коммит делается только после их коммита.

осталось: смок тест-кнопки на реальном (tauri) бинаре — в браузере она честно даёт «в браузере системных уведомлений нет»; ладдер в интеграциях недоступен без подключённого канала, это по дизайну.

## общий тумблер (добавлен после первой версии)

- выключение: `reconcileNotifications` получает пустой список маршрутов — релей снимает то, что эта сессия поставила в очередь, и новые напоминания не уезжают; плюс `setAssistantForRoutes(..., false)` — бот молчит; системные тосты начинают работать вместо канала.
- **дырка, которую видно честно**: задачи, поставленные в очередь релея прошлой сессией, тумблер не снимет — клиент помнит только свои `armedKeys`, и после перезапуска он их не знает. правильное лечение — эндпоинт «заглушить маршрут» на релее, тогда тумблер станет одним вызовом. отложено, релей в этой задаче не трогали.
- снятие очереди на этой сессии идёт с задержкой до 30 с (тик `useNotifyArm`), мгновенного срабатывания нет.
- вкладка — список и детали в одном компоненте (`isTelegramOpen`): шестерёнка это афорданс, кликается вся строка, чтобы не было `button` внутри `button` (e2e это стережёт).
- история: коммит параллельной сессии `212d3ee` (`feat(settings): updates tab ...`) затащил мои две строки регистрации вкладки — их нельзя было отделить, `Plug` и `ArrowDownToLine` живут в одной строке импорта и в одном union-типе. дерево зелёное начиная с моего коммита, промежуточный красный.
