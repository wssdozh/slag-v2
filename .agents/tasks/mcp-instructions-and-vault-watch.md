# mcp: инструкции сервера и видимость правок, сделанных снаружи

- **цель**: агент, подключённый по mcp, получает при `initialize` короткий блок правил (порядок вызовов, расписание полями, свежесть данных) и не пишет «каждый вторник» в текст; правка заметки снаружи приложения (mcp, obsidian, скрипт) появляется в ленте без `ctrl+r`; внешняя правка не затирается первым же сохранением из приложения.
- **трогаем**: `src/mcp/instructions.ts` (новый), `src/mcp/index.ts`, `scripts/mcp-instructions.test.mjs` (новый), `src/lib/storage/vaultWatch.ts` + `vaultWatchDiff.ts` (новые), `src/lib/storage/writeGuard.ts` (новый), `src/lib/storage/vaultFiles.ts`, `src/lib/storage/index.ts`, `src/context/hooks/useVaultWatch.ts` (новый), `src/context/AppContext.tsx`, `src/lib/sync/syncEngine.ts`, `src/lib/sync/entities/registry.ts`, `scripts/vault-watch.test.mjs` (новый), `package.json`, `docs/mcp-guide.md`.
- **не трогаем**: rust (`notify`-вотчер остаётся возможным апгрейдом, а не частью этой задачи), протокол синка и релей, схему `save_note`, формат фронтматтера, теги/ген заголовка/андроид-долги — это отдельные задачи.
- **готово когда**: `npm run check` → `0 warnings and 0 errors`; `npm run test:scripts` зелёный, включая живую проверку `initialize.instructions` на собранном `dist/mcp`; `npm run build` проходит; правка заметки через mcp видна в интерфейсе ≤ 3 с без перезапуска.
- **уже выяснили**: `@modelcontextprotocol/sdk` 1.32.2 принимает `instructions` вторым аргументом `McpServer` (`server/index.d.ts:13`), а `src/mcp/index.ts` его не передавал вовсе. MCP читает диск на каждом вызове, поэтому правки приложения ему видны сразу; обратное не работало никогда — у приложения нет ни нативного вотчера (`notify` в `Cargo.toml` нет), ни подписки на файлы. `dist/mcp/index.js` в конфиге dsh был путём на старый worktree — заменён на основной (`npm run mcp:install -- --clients dsh` пишет то же самое).

после работы допиши: что оказалось не так, как думали, и что осталось.

## как прошло

- `origin` пришлось расширить до `'local' | 'remote' | 'external'`, вместо отдельного флага «это извне». Причина: `AppContext` обновляет список на всех событиях, кроме `remote`, а синк ставит операцию на всех, кроме… тоже `remote`. Одна третья метка разводит эти два правила двумя однострочными правками (`syncEngine.ts`, `entities/registry.ts`) — а флаг требовал бы правок в каждом потребителе.
- `saveItem` всегда штампует `updatedAt: Date.now()`, поэтому guard не может сравнивать с только что сохранённым значением: он берёт `updatedAt` предыдущей версии из индекса — ту, которую человек видел. Иначе «файл новее» не сработал бы никогда.
- юнит-раннер для TS в репозитории всё-таки есть (`node --test` + type stripping, `scripts/mcp-note-patch.test.mjs` так и работает), но node не резолвит импорты без расширения. Поэтому чистые половины задачи вынесены в модули без рантайм-импортов: `vaultWatchDiff.ts` и `writeGuard.ts`. Импортировать `vaultWatch.ts` из теста нельзя — он тянет `@tauri-apps/*`.
- тест на собранный бандл сам себя пропускает, если `dist/mcp` старше исходников: иначе `npm run test:scripts` падал бы у каждого, кто не пересобрал mcp, и это читалось бы как сломанный тест, а не как устаревшая сборка.
- вотчер сделан поллингом (`stat` раз в 2 с, только видимое окно, только десктоп), а не `notify` в rust: нативный вотчер потребовал бы пересборки приложения, которую локально не гоняют, и нового крейта ради 85 файлов.
- тост о «заметка обновлена снаружи» убран из плана на ходу: внешний редактор сохраняет на каждое нажатие, и вместо уведомления получался бы поток. Обновления приходят молча (лента и так меняется на глазах), тосты остались на удаление и на конфликт — там человеку есть что решать.

осталось: папка, созданная через `create_folder`, всё ещё не появляется в интерфейсе без перезапуска — `state.json` лежит вне `notes/` и в свип не входит. Дальше по вкусу: следить и за ним, либо считать это отдельной задачей. Внешняя правка уезжает на релей не сразу, а следующим локальным сохранением этой заметки: `external`-события сознательно не пушатся, иначе релей эхом вернёт ту же заметку и два устройства начнут пинг-понг.
