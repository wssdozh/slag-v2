# B13: живой предпросмотр markdown в редакторе

- **цель**: в фокус-редакторе строка под кареткой показывает сырую разметку (`#`, `**`, `- `, `1.`, `- [ ]`), а остальные строки — оформление; списки рендерятся как списки.
- **трогаем**: ничего в `src/` — см. «уже выяснили». Отчёт и разбор — этот файл.
- **не трогаем**: `@atomic-editor/editor` в `node_modules` (junction в основную копию), форк/патч зависимости, `MarkdownRenderer` карточек.
- **готово когда**: в `#fullscreen-editor-root` на строке с кареткой видны сырые маркеры списков, а карточки ленты не разъехались.
- **уже выяснили**: предпросмотр целиком живёт в стороннем пакете; в репозитории только монтирование.

## Где живёт предпросмотр

`src/components/Editor/FullscreenEditor.tsx:572` монтирует `AtomicCodeMirrorEditor` из
`@atomic-editor/editor@0.6.2` (npm, github.com/kenforthewin/atomic-editor). Своих
CodeMirror-расширений для инлайн-предпросмотра в `src/` нет: `extensionsForEditor`
(`FullscreenEditor.tsx:197`) добавляет только `attachmentEmbeds`. Тема и правки внешнего вида —
`src/index.css:428-539`.

Вся логика «сырой текст под кареткой» — в
`node_modules/@atomic-editor/editor/dist/inline-preview.js`:

- `buildInlineDecorations` считает `activeLines` по `view.hasFocus` + `state.selection`
  (строки 340-357);
- `HIDEABLE_SYNTAX` (строки 182-192) — `HeaderMark`, `EmphasisMark`, `CodeMark`, `LinkMark`,
  `QuoteMark` и т.п. — раскрываются на активной строке;
- `ListMark` (строки 503-594) и `TaskMarker` (строки 634-653) **не смотрят на `activeLines`**:
  буллет всегда заменяется виджетом `•`, `- [ ]` — чекбоксом, у ordered-маркера всегда
  прячется пробел. Конфига у `inlinePreview()` нет (`InlinePreviewConfig` — только
  `onLinkClick`), через `extensions` уже заменённый диапазон обратно не показать.

## Что проверено в браузере (Playwright, порт 5212)

- `# Заголовок`, `**жирный**` на строке с кареткой раскрываются в сырой вид через ~100 мс
  после клика (freeze-таймер пакета), т.е. механизм живой: `activeLines`/`hasFocus` работают.
  Проверено и кликом, и `ArrowDown/ArrowUp`, и программным `view.dispatch`.
- `- пункт`, `1. пункт`, `- [ ] задача` на строке с кареткой остаются оформленными — сырые
  маркеры не появляются никогда. Это и есть жалоба «на строке с курсором всё ещё рендерится».
- Списки при этом рендерятся: в редакторе — виджеты `•`/чекбоксы и alcove для `1.`; в карточке
  ленты `MarkdownRenderer` даёт `<ul class="list-disc list-inside">` / `<ol class="list-decimal">`
  с видимыми маркерами (`getComputedStyle` → `list-style-type: disc/decimal`). Заявленное
  «списки вообще не рендерятся» на базе `feat/landing-media` (6155b7d) не воспроизводится.
- Две копии CodeMirror исключены: `npm ls @codemirror/state @codemirror/view` в корне и в
  `node_modules/@atomic-editor/editor` — всё `deduped` на 6.7.6 / 6.43.15.
- CSS пакета на месте (`dist/styles/inline-preview.css`, `exports["./styles.css"]`), правила
  `.cm-atomic-list-marker` / `.cm-atomic-bullet` есть; `src/index.css` их не перекрывает.

## Что оказалось не так, как думали

- «Две копии codemirror» — не подтвердилось, дедуп в порядке.
- «Рендер списков сломан» — на этой базе не воспроизводится ни в редакторе, ни в карточке.
  Второй скриншот из задачи — это CommonMark lazy continuation: после пункта `- [ ] ...`
  строки `2. ...`/`3. ...` без пустой строки и с нулевым отступом парсер считает продолжением
  того же пункта, а не новым списком. Приложению тут чинить нечего, это семантика разметки.
- Единственный воспроизводимый дефект — маркеры списков и чекбоксы не раскрываются на
  активной строке. Это зашито в пакете и в репозитории не чинится.

## Что осталось (для настоящего фикса)

1. Форк/патч `@atomic-editor/editor`: в обработчиках `ListMark` и `TaskMarker` учитывать
   `activeLines` (как это уже делают `HeaderMark`/`HorizontalRule`), т.е. на активной строке
   не заменять маркер виджетом, а показывать сырой `- `, `1. `, `[ ]`.
2. Либо issue в github.com/kenforthewin/atomic-editor с этим поведением и апгрейд, когда выйдет.
3. После форка — e2e на `#fullscreen-editor-root`: строка с `- [ ]` под кареткой содержит `[ ]`,
   соседняя — чекбокс; карточка ленты не меняется.

`npm run check` — зелёный (0 warnings, 0 errors). Правок в `src/` нет.
