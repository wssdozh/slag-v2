# Автослияние соседних строк, абзацев и тегов

- **цель**: сохранить независимые правки двух устройств без ручного разбора.
- **трогаем**: текстовый merge, правила для tags, тесты реплик и документацию синхронизации.
- **не трогаем**: UI, ручной повтор, сервер, протокол, журнал и живые заметки.
- **готово когда**: сценарии сходятся в обоих порядках доставки, конфликтные варианты не порождают новые ревизии, локальный smoke проходит при 0/100 мс RTT.
- **уже выяснили**: аудит показал ложные конфликты на соседних строках/абзацах и тегах, а также успешное построчное слияние, после которого заголовок неожиданно становился кодом.

---

## Итог

- Без внешней зависимости: существующие уникальные якоря и один точный диапазон замены на каждую сторону в спорном промежутке. Визуальный LCS не переиспользован: он выбирает одно из возможных выравниваний, а здесь неоднозначность должна оставить конфликт.
- Для ограждений кода недостаточно сравнить список самих маркеров: одинаковый маркер можно переместить. Ограждения не участвуют в выравнивании; проверяется, попадают ли они в диапазон изменений после отсечения одинаковых краёв. Если ограждения присутствуют, новый проход для соседних строк не включается.
- Повтор матрицы из 33 сценариев в обоих порядках: четыре бывших конфликта объединены, два небезопасных результата Markdown теперь останавливаются. Итого 12 объединений, 2 без записи, 19 конфликтов. Ручной повтор не изменялся.
- 290 скриптовых тестов, проверка типов и сборка прошли. Smoke с третьим писателем, потерянной квитанцией и 0/100 мс добавленного RTT — зелёный.
