## 8. Мерж и проверки

После волны, по каждой ветке:

```powershell
git -C ".agents\worktrees\bugs-integr" merge --no-ff fix/<slug> -m "merge: <slug>"
```

- Конфликт: чинить руками в интеграции, сохраняя оба намерения. Если конфликт
  содержательный (две задачи лезут в одну логику) — выбрать вариант, который
  закрывает обе задачи, и записать в отчёт.
- После каждого мержа: `npm run check` в интеграции. Красное — починить сразу.
- После волны: целевые e2e (`e2e/slag/<зона>`) с `PLAYWRIGHT_WORKERS=1`, скриншоты.
- После всех волн: `npm run build` в интеграции один раз.
- Мержить только зелёные ветки. Красную — починить в её worktree и перемержить.
- Снять junction и удалить worktree задачи после мержа:
  `Remove-Item ".agents\worktrees\bugs\<slug>\node_modules" -Force;
   git worktree remove ".agents\worktrees\bugs\<slug>"; git branch -d fix/<slug>`

Финальные проверки обязательны: `npm run check` (две строки), `npm run build`,
e2e по затронутым зонам, наличие скриншотов.

## 9. Отчёт

Файл: `.agents/reports/slag-bugfix-2026-11-16.md` в интеграционной ветке,
закоммитить как `docs(report): slag bugfix wave report`. Копию положить в основную
копию по тому же пути (не коммитить).

Разделы, все обязательны:

1. **Сводка** — сколько задач взято, исправлено, частично, не воспроизвелось, скип.
2. **Таблица по B1–B14** — id, что просили, статус, файлы, `+/-`, проверка, хвост.
3. **Подробно по каждой** — корневая причина (одна-две фразы), что изменено,
   чем проверено, скриншот, что осталось. Если корень не найден — честно «не нашёл».
4. **Не трогал** — таблица 10 фич из §4 и файлы вне зоны (лендинг, relay, theme.css,
   зависимости, e2e-конфиг), почему.
5. **Мерж** — какие ветки вошли, какие конфликты были и как разрешены.
6. **Проверки** — check/build/e2e/скриншоты, что зелёное, что не гонялось и почему.
7. **Риски и хвосты** — что требует устройства (Android sync без adb), что требует
   ручного взгляда, где фикс может не покрыть редкий сценарий.
8. **Git** — база, интеграционная ветка, `git log --oneline base..integration`,
   `git diff --stat base..integration`.

Отчёт большой, но без воды: факты, файлы, причины. В финальном ответе пользователю —
короткая сводка и ссылка на файл.

## 11. Стоп-условия

- Три одинаковых падения `check` на одну задачу — стоп по этой задаче, лог в отчёт,
  идёшь дальше. Четвёртой попытки нет.
- Фикс требует новой фичи/зависимости/схемы данных — не делать, записать.
- Что-то не воспроизводится после разумной попытки — «не воспроизвёл» с деталями,
  без выдуманных правок.
- Файл задачи противоречит коду — чинить реальный корень, а не текст задачи.
