# авто-теггирование: контекст хранилища вместо голого текста

- **цель**: модель тегирует заметку, понимая, что за проект перед ней: видит дерево папок с описаниями, текущую папку и её родителя, словарь существующих тегов с частотой. Сначала переиспользует тег, новый создаёт только для устойчивой темы уровня категории, пустой массив — нормальный ответ. То же правило работает в пакетном триаже.
- **трогаем**: `src/lib/ai/taggingPrompt.ts` (новый: чистые сборщики промпта), `src/lib/ai/aiService.ts` (`categorizeDraft`, `triageInboxItems`, `localHeuristicTags`, `collectTagUsage`), `.agents/tasks/ai-tagging.md`.
- **не трогаем**: сигнатуры и имена `categorizeDraft` / `triageInboxItems` / `generateSmartTags`, формат ответа (`targetFolder` / `tags` / `reason` / `suggestedTitle`), стиль тегов из настроек, UI, `prompt.ts` ассистента, e2e/playwright, сборки.
- **готово когда**: `npm run check` печатает `0 warnings and 0 errors`; промпт собирается чистой функцией из словаря, папок и текста; новый тег невозможен без устойчивой темы; heuristic-фолбэк переиспользует словарь первым.
- **уже выяснили**: имена из карточки (`triageInbox`, `smartTagging`) в коде не существуют — реальные экспорты `triageInboxItems` и `generateSmartTags`, их и оставляем. Отдельного TS-юнит-раннера в репозитории нет: `npm run test:scripts` гоняет только `node --test` по `.mjs`, остальное — Playwright e2e. Счётчики тегов уже считает `storage.getVaultStats().tags`, отдельный API заводить не нужно.

---

после работы допиши: что оказалось не так, как думали, и что осталось.

## как прошло

- `getAllExistingTags()` отдаёт алфавитный список без частот; частоты берём из `storage.getVaultStats().tags` — один проход по записям, нового метода в storage не понадобилось.
- `categorizeDraft` не получает тип и заголовок (сигнатура зафиксирована), поэтому в промпте черновика есть папка и текст, а тип/заголовок приходят только в триаже.
- `settings.allowNewTags` был мёртвым полем: теперь он доезжает до промпта (при выключении — строго словарь) и до heuristic-фолбэка.
- TS-юнит-раннера нет, тест не заводили. Чистый сборщик проверен разовым прогоном в node 24 (type stripping, временный файл вне репозитория).

осталось: `suggestedTitle` в черновике по-прежнему приходит от модели, а не из первого заголовка текста; кэш частот тегов не инвалидируется отдельно — считается на каждый вызов (проход по записям, дёшево).
