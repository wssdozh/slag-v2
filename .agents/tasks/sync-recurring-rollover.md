# Не отправлять устаревший автоперенос на ручной разбор

- **цель**: уже устаревшее число для повторяющейся задачи не блокирует человека и не откатывает подтверждённый срок.
- **трогаем**: захват автопереноса в журнале, проверку кандидата, очистку старых альтернатив, проверку пересечения уже совпавших полей и тесты.
- **не трогаем**: установленную сборку, рабочую комнату, ручные изменения и формат сетевых операций.
- **готово когда**: ранее сохранённая альтернатива с 23-м закрывается при подтверждённом 24-м без сетевой записи; конкурирующие автопереносы не порождают разбор; независимые ручные изменения и неоднозначные варианты сохраняются.
- **уже выяснили**: в старом Android-снимке ежедневной задачи отличается только срок. На Windows подтверждён непрерывный переход `33 → 262` с более поздним автопереносом. Старая очередь не записывала причину правки: для legacy введено узкое правило истечения даты, а не предположение об авторстве.

## Что подтвердили отдельные проверки

1. После полного догона старый снимок ежедневной задачи `23 → 24` убирается из разбора без записи на релей. Остаются изменённый текст, другое напоминание, другая периодичность, будущий срок, сомнительная или более свежая отметка времени и вариант из восстановления диска.
2. Новый явно автоматический перенос отделяется от пользовательской правки. Из холодной очереди после истечения истории на Python-релее сохранились более поздний срок, локальный заголовок и тег с другого устройства; отправился только заголовок, три реплики на `165`. Ручное расхождение сроков в контроле сохраняется на разбор.
3. Независимая проверка старых разборов воспроизвела ложную альтернативу для Markdown-правки, уже целиком записанной другим устройством. Теперь точное совпадение завершает операцию только при доказанной непрерывности. Такое же содержимое после удаления и восстановления сохраняет прежнее защитное поведение.
4. Независимая проверка автоматических полей подтвердила лишний разбор на реальном `mergeNote`: одинаковое завершение пересекалось с добавленным отдельно напоминанием; одинаковый перенос — с добавленным отдельно напоминанием. В проверку независимых изменений теперь не попадают совпадающие поля задачи. Реально расходящиеся расписание и завершение по-прежнему не комбинируются вслепую.
