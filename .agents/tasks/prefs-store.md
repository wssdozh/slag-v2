# префы: фундамент вместо localStorage

- **цель**: в native-сборке `localStorage` не трогается вообще, настройки живут в `<AppData>/settings.json`; в браузерной сборке (dev + Playwright) `localStorage` остаётся бэкендом за тем же интерфейсом. Остальной код читает и пишет префы синхронно из памяти, поэтому переезд вызовов — механическая замена `localStorage.getItem` → `getPref` в следующих волнах.
- **трогаем**: `src/lib/storage/prefs.ts`, `src/lib/storage/prefsBackend.native.ts`, `src/lib/storage/prefsBackend.browser.ts`, `src/main.tsx` (одна строка в `boot()`), `scripts/no-localstorage.test.mjs`, этот файл.
- **не трогаем**: вызовы `localStorage` в остальном `src/**` (их переписывают волны, на них трещотка и baseline), `package.json` (тест вписывает оркестратор), `docs/CODE_MAP.md` (генерится), `state.json` хранилища (отдельный файл, другой владелец), `STORAGE_KEYS` (ключи те же).
- **готово когда**: `node --test scripts/no-localstorage.test.mjs` зелёный и baseline честный; `npm run check` — две строки `0 warnings and 0 errors`; файла `settings.json` до первого `setPref` не существует.
- **уже выяснили**: ни одно текущее чтение не происходит на этапе импорта модуля, значит одного `await initPrefs()` в `boot()` до рендера хватает; `queueStateWrite` — готовый образец очереди с коалесингом; `fs:allow-appdata-write-recursive` в `src-tauri/capabilities/default.json` включает `write-all`, а тот — `allow-rename`, то есть временный файл + `rename` разрешены и на десктопе, и на Android; `\blocalStorage\.` сегодня матчится в 32 файлах `src/**`.

---

## что оказалось не так, как думали

- бэкенд принимает не полный снапшот, а только изменившиеся ключи (`Record<string, string | null>`, `null` — удаление). Целый снапшот нельзя: браузерный бэкенд писал бы поверх `localStorage` все ключи разом, включая чужие, а native — читал бы файл на каждый flush всё равно, потому что диф нужен, чтобы не потерять ключи, записанные другим окном/сборкой.
- `rename` пишет поверх существующего файла (MoveFileEx с replace), так что временный файл можно оставлять рядом с `settings.json`: имя фиксированное, `.tmp` не копится.
- ключи, записанные до `initPrefs()`, не теряются: загрузка снапшота не затирает ключ, у которого уже есть pending-значение, а после инициализации очередь досылает его в файл. Иначе `setPref` из раннего обработчика молча оставался бы только в памяти.
- `initPrefs()` не rejects: битый/отсутствующий файл и ошибка чтения — это пустой снапшот плюс `logger.scope('FS').warn`, а не экран падения. В `boot()` он всё равно стоит в общем try/catch, но падать оттуда по префам нечему.
- коалесинг — только «в одном тике»: очередь на промисах, как у `queueStateWrite`, без `setTimeout`. Серия `setPref` подряд даёт одну запись, но ширина сайдбара, которую тянут мышью, даёт запись на каждое событие указателя — ровно как `localStorage.setItem` до переезда. Потолок осознанный: дебаунс на таймере — это отдельная правка, если профиль покажет нагрузку на диск.
- трещотка проверяет ещё и обратное: файл из baseline, который больше не матчится, — красный тест. Иначе список тихо гниёт и перестаёт быть честным.

## что осталось

- волны переписывают 32 файла baseline; каждая вычёркивает свою строку.
- `readJson.ts` пока живёт своей жизнью: его вызовы перейдут на `getPrefJson`, после чего модуль удаляется.
- `logger.ts`, `secretStore.ts`, `usage.ts` читают `localStorage.length`/`key(i)` — это не `\blocalStorage\.`-паттерн для трещотки, но переезд им тоже нужен; отдельная волна.
- несколько окон (detached-окна, быстрый композер) держат по своей карте: правка в одном окне не долетит в другое до перезагрузки, `BroadcastChannel`/`storage`-события не подписаны. `localStorage` в браузере это умел сам; на native такого канала и не было. Отдельная задача, фундамент её не решает.
- `npm run build` проверил раскладку: `prefsBackend.native-*.js` (892 Б) и `prefsBackend.browser-*.js` (312 Б) — отдельные ленивые чанки, `settings.json` встречается только в native-чанке, в главном бандле его нет.
