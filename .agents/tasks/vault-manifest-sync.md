# манифест хранилища в синке, метла вложений, быстрый старт

- **цель**: после старта приложение само сверяет свой корень с тем, что лежит в комнате, и при расхождении один раз переотправляет состояние; панель «состояние» показывает строку «сервер: сходится / расходится». висячие вложения убираются в архив чистки штатным ремонтом. старт не читает корзину последовательно.
- **трогаем**: `src/lib/sync/manifestChannel.ts`, `src/lib/sync/manifestSync.ts` (новый), `src/lib/sync/syncEngine.ts`, `src/lib/sync/pushBundle.ts`, `src/lib/sync/types.ts`, `src/hooks/ui/useIntegrity.ts`, `src/components/Settings/vault/integrity/IntegrityPanel.tsx`, `src/components/Settings/vault/integrity/IntegritySection.tsx`, `src/lib/vault/integrity/types.ts`, `src/lib/vault/integrity/repair.ts`, `src/lib/vault/integrity/scanners.ts`, `src/lib/vault/integrity/snapshot.ts`, `src/lib/storage/integrityService.ts`, `src/lib/storage/vaultFiles.ts`, `src/context/AppContext.tsx`, `scripts/vault-doctor.mjs`, `scripts/vault-snapshot.mjs`, `scripts/integrity-*.test.mjs`, `e2e/slag/vault_integrity.spec.ts`, `docs/sync-architecture.md`, `AGENTS.md`.
- **не трогаем**: релей (`wssdozh/slag-relay`) — маршрут `/manifest` уже в проде и держит только `root` + `folders`; шифрование бандлов; `applyBundle` (LWW не меняется); раскладку модулей.
- **готово когда**: на пк и ноуте в логе `манифест v1: …` с одинаковым корнем и «корень сходится»; `vault-doctor` на пк не находит висячих вложений; `npm run check`, `npm run build`, `node --test`, плейрайт зелёные; dev-релиз собран и обе машины на нём.

**что оказалось не так, как думали**

1. **публикация до чтения — это сверка с собой.** релей держит одну строку на пару (комната, хранилище), поэтому порядок «POST, потом GET» возвращал устройству его же корень. в dev.37 оба устройства сказали «корень сходится», имея 21 и 22 папки. порядок исправлен: GET → решение → POST (`65b8fc9`).
2. **парсер ссылок рубил путь по пробелу.** `![Pasted image 1.png](.attachments/Pasted image 1.png)` давало ссылку `.attachments/Pasted`, а настоящая картинка выглядела ничейной. в dev.38 это значило, что «Почистить» унесло бы в архив 56 файлов, которые заметки показывают. исправлено в `snapshot.ts` и `vault-snapshot.mjs`, ссылки на `http`/`data` больше не считаются файлами хранилища (`9ee626b`).
3. **две заметки физически лежали не в своей папке.** `folder: Личное/Отдых` в frontmatter, а файл — в `Входящие/`. содержимое и `updatedAt` одинаковые, поэтому LWW не мог выбрать победителя, и корни не сошлись бы никогда, сколько ни переотправляй. это тот самый случай, ради которого сверка и нужна; лечится `path-mismatch`-сканером, но пока руками.
4. **корзина была медленной не из-за диска**: чистый `fs` читает 270 файлов за 206 мс подряд и 59 мс по восемь. 1.5 с давали 270 последовательных IPC.
5. **легаси `.attachments` внутри `notes/`** (12 файлов) — приложение его не читает, поэтому 11 картинок, которые заметки называют, не находились. перенесено в корневой `.attachments`, после чего врач показал ноль находок.
6. **`npm run test:scripts` не запускал `integrity-{snapshot,manifest,manifest-wire,store}`** — четыре файла тестов жили сами по себе. добавлены, набор 162 → 208.

**итог в цифрах**

- висячих вложений: 67 → 0 (56 файлов в `.trash/.hygiene/2026-11-19T07-46-44-363Z/attachments/` и второй проезд за одним).
- оба устройства: 89 заметок, 21 папка, **побайтово одинаковые `.md`** (сверено хешами), одинаковый корень манифеста и «корень сходится» в логе.
- первый кадр ленты и фазы чтения с диска теперь в логе — цифры для следующего захода.

**что осталось**

- ноут: своя метла вложений (76 файлов в его `.attachments`) — теперь это одна кнопка в панели «состояние» на dev.39 и выше.
- сверку хорошо бы связать со сканером: расхождение корней сейчас лечится только переотправкой, а причина бывает в `path-mismatch` (случай 3).
- `syncManifest` пересчитывает корень целиком после каждой пачки правок (дебаунс 5 с): при 5000 заметках ~180 мс на проверку, инкрементальных листьев нет.
- релей по-прежнему не хранит листья — ремонт полный, точечная догрузка требует эндпоинта «дай заметку по id».
- `release-run.mjs` после `git push origin master` запускает второй прогон поверх пуш-триггера. либо `--no-push`, либо не диспатчить руками.
