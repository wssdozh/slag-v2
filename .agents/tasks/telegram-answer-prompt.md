# ответ из телеграма: свой формат и короче общий режим

- **цель**: ответ из бота читается как сообщение в телеге (заголовок + пункты, без markdown), а общий ассистент отвечает только на заданный вопрос
- **трогаем**: `src/lib/ai/prompt.ts`, `src/lib/ai/types.ts`, `src/lib/ai/orchestrator.ts`, `src/lib/notify/assistant.ts`
- **не трогаем**: `relay/**` (ответ и так уходит экранированным plain text), формат напоминаний
- **готово когда**: `npm run check` и `npm run build` зелёные; вопрос «что по задачам?» из бота даёт первую строку-ответ и список задач, без «хочешь, расставлю?»
- **уже выяснили**:
  - релей отправляет ответ через `tg_escape(text)` с `parse_mode: HTML`, то есть любая разметка из модели приходит символами
  - промпт для приложения и для телеги был один, поэтому бот отвечал разговорным абзацем на 5 строк
  - локальный фолбэк (`buildAssistantAnswer`) отдавал одну строку «на связи · задач на сегодня: N», без самих задач

---

после работы допиши: что оказалось не так, как думали, и что осталось.

## добавлено позже: статусы в одном сообщении

- **что**: четыре состояния одного bubble — `🔎 ищу устройство…` → `⌛ передал на «имя»` → `✍️ печатает ответ…` → сам ответ. новое сообщение не отправляется ни на одной стадии.
- **как**: `relay/server.py` создаёт request и placeholder **до** выбора устройства; устройство сообщает о старте модели по WS (`{"type":"assistant_stage","id":…,"stage":"thinking"}`), релей переписывает тот же message_id.
- **почему так**: релею нечем отличить «устройство думает» от «устройство умерло», поэтому стадию думания сообщает клиент; остальные три релей знает сам.

### что оказалось не так

- `finish_assistant_request` ставит `answered_at`, а правка статуса это поле проверяет: если закрыть запрос до правки, «устройства нет в сети» уже не отрисуется. править надо до закрытия.
- на клиенте стадию нельзя репортить на пути catch-up (`pendingAssistant` по HTTP): там нет сокета, в который отвечать; параметр сделан необязательным.
- deployed релей был на 10 коммитов позади и вообще без `tg.py`; первый деплой обязан ехать двумя файлами, иначе сервис падает на импорте.

### что осталось

- стадия «ищу устройство» при одном кандидате живёт доли секунды — на глаз почти не видна, и это нормально.
- если устройство взяло вопрос и умерло, bubble навсегда останется «передал на …» до TTL; отдельного «устройство не ответило» нет.
