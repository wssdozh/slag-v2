# SLAG: отзывчивость, нативное I/O и быстрый синк

- **цель**: быстрее запуск, рабочая лента и первый интерактивный кадр на Windows, Linux, Android и вебе; плавные окна/меню и стабильный скролл при обновлениях; минимальная безопасная задержка доставки между устройствами.
- **трогаем**: загрузку приложения, переходы поверхностей, якорение ленты и FLIP, измеренные узкие места чтения vault и медиа, телеметрию и горячий путь синка; затем только подтверждённые дубли, инструкции и карту модулей.
- **не трогаем**: рабочую копию `feat/note-replica`, живые профили и комнаты, форматы Markdown/YAML и sync wire, надёжность журнала/CAS/курсоров. Пуш, CI, установка, слияние в master, релиз и изменение отдельного релея — по отдельному согласованию.
- **готово когда**: реальный первый тап выполняется без второго касания, p90 отклика целится в ≤100 мс; в детерминированной ленте выживший якорь отклоняется ≤2 CSS px; измеренные оптимизации ускоряют целевой UI-сценарий ≥15%, Rust-путь ≥20% времени или целевого пика памяти для медиа. Нативный gate синка: p95 ≤1000 мс от действия до видимой записи на B при стабильной сети и отдельно при 0 и 100 мс добавленного RTT. Нет опыта на устройстве — метрика не подтверждена.
- **уже выяснили**: базовый коммит `1c29602c88aecf77cce4bf362cd5830acab42aee`; предыдущий нативный gate остался открыт (`relay-authority.md`), 161/244 мс — старый стенд с репликами, а не UI/диск. Текущий `note-device-stress` проверяет сходимость, не latency. Размер бандла по `perf-startup` не равен времени готовности. Причина первого тапа не доказана.

## Владение и порядок

1. База и адресные регрессии. Одинаковые синтетические fixtures на 100/1000/5000 записей, медиа отдельно. Для UI ≥20 парных повторов; для нативного живого синка ≥40 на направление/сеть, p50/p95/max/таймауты, отдельно 64 КиБ, пачки, медиа и офлайн-догон.
2. `perf/startup-input`: критический путь boot, лёгкий отклик до импорта редактора, выборочный прогрев только при выигрыше. `perf/surface-motion`: enter/exit/resize, reduced motion, фокус/LIFO/back, реверс. `perf/stable-feed`: один владелец позиции, bounded FLIP, сохранение чтения при синке и resize. `perf/native-vault`: разнести I/O и парсинг, сравнить пакетное безопасное чтение Rust с TS на нативных платформах. `perf/visible-media`: отсечение вне экрана, память и bounded I/O, Rust только по трассе. `perf/device-sync`: разметить локальный журнал, очередь, WS/relay, проекцию и UI; устранять измеренные ожидания с сохранением идемпотентности, атомарных групп и restart recovery.
3. Integrator ревьюит каждую ветку, не пересекает владельцев файлов. Общие файлы и тяжёлые сборки последовательно. Cleanup + `npm run map:code`; `npm run check`, `npm run build`, `npm run test:scripts`, целевые и полные Playwright, sync/audio с одним воркером. Нативные артефакты и реальные устройства — по согласованию, только staging.
