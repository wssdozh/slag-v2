# клиентский бэкенд на расте: что переносим, что нет

- **цель**: открытие хранилища и запись заметок перестают быть узким местом и перестают
  быть хрупкими; домен хранилища живёт в растовом ядре, ui остаётся на ts
- **трогаем**: `src/lib/storage/*` (за фасадом `StorageService`), `src/lib/sync/applyBundle.ts`
  (только если решим), `src-tauri/src/core/` (новый крейт-модуль), `src/types/index.ts` (генерация)
- **не трогаем**: `src/components/**`, `src/context/**`, `src/hooks/**`, `src/lib/ai/**`,
  `relay/**`, формат `.md` и YAML frontmatter (это контракт пользователя с его файлами)
- **готово когда**: `vault_scan` на 1000 заметках укладывается в 100 мс на десктопе и в 250 мс
  на телефоне, запись атомарна (temp+rename), `npm run check && npm run build` зелёные,
  e2e-пачка зелёная, ни одного нового спиннера в ui
- **уже выяснили**: см. блок «факты» ниже — цифры, которые дорого искать второй раз

---

## гипотеза

если перенести в растовое ядро ровно три вещи — сканирование/запись хранилища, байты
вложений и крипту — то открытие хранилища на 1000 заметок ускорится с ~700–900 мс до
~50–80 мс, а запись заметки перестанет терять данные при падении процесса. мерим:
`performance.now()` от клика по хранилищу до отрисованной ленты, и число «битых» заметок
после `kill -9` в момент сохранения.

## факты (замерено здесь и сейчас)

- клиентский домен: **163 модуля / 29 750 строк** в `src/lib` + `src/hooks` + `src/context`
- из них трогают `@tauri-apps/*`: **17 файлов / 4 660 строк** — это и есть «бэкенд в фронте»
- вообще не касаются react/context/tauri: **108 файлов / 19 249 строк** — чистый домен
- `vaultFiles.ts` — **62 файловые операции** на 507 строк; в `scanNotesDir` один
  `readTextFile` на каждую заметку (параллелизм 8), в `flushItemToDisk` — `writeTextFile`
  прямо на целевой путь, **без temp+rename**
- замер парсера (node 24, V8, заметка 796 байт, `parseMarkdownToItem`):
  **193 мс на 1000 заметок**, сериализация **79 мс на 1000**
- батч 1000 заметок в JSON = **0.82 МБ**, `JSON.parse` = **1.9 мс**
- ipc по замерам сообщества: **~0.5 мс на `invoke`**, ~1000 json-вызовов/с, payload >100 КБ
  стоит дорого и стрингифицируется на главном потоке
  ([внутренности ipc](https://stuffbucket.github.io/skills/catalog/tauri-architecture-ipc-internals),
  [бенчи state-sync](https://777genius.github.io/state-sync/benchmarks))
- вложения идут **base64 через json**: `persistAll` декодирует data-url в js и отдаёт
  `Uint8Array` в `writeFile`; в коде уже стоит комментарий про «сто мегабайт строки на альбом»
- `crypto.subtle` есть **off-main-thread** — pbkdf2 на 100k итераций не даёт столла,
  а даёт задержку разблокировки ~100–400 мс; значит перф-аргумент за растовую крипту слабый
- в проекте **нет юнит-тест-раннера**: домен проверяется только 21 тыс. строк playwright
- на расте уже есть 2 041 строка и 19 команд (`platform`, `deeplink`, `secure_store`,
  `updater`, `media_plugin`) — ядро не с нуля, а продолжение

## ux-путь

новых экранов нет. путь тот же: запуск → выбор хранилища → лента. шагов не прибавляется.
единственный риск регресса — пустая лента на кадр, пока идёт команда; критерий приёмки:
если появился спиннер там, где его не было — это баг, а не прогресс.

## план (черновик, ждёт «го»)

1. замер и инструментирование: `logger.scope('PERF')` вокруг `syncCurrentVaultFs` и
   `flushItemToDisk`, таблица 100/1000/5000, десктоп + телефон. без этого дальше не идём
2. `src-tauri/src/core/` + typed-команды; типы — генерируемые, `src/types/index.ts` остаётся
   точкой входа для ts (переэкспорт), правило в `src/AGENTS.md` правится
3. `vault_scan` одним батчем (заметки + папки + состояние), ts-фасад тот же
4. атомарная запись: temp+rename, тест на падение, плюс сверка «что на диске vs что в памяти»
5. `attachment_write` из байтов/пути, а не из base64-строки
6. крипта: pbkdf2/ecdsa/aes-gcm + bip39, паритет на тест-векторах против текущих ts
7. (опционально) `backup_zip` на расте
8. vitest для оставшегося ts-домена — закрывает дыру в тестах

## решения (от 2026-11-14)

- болит всё четыре: открытие, вложения, краш-запись, чистота. значит порядок важности:
  открытие → запись → вложения → границы
- целевой объём **5000+ заметок и телефон**. это меняет цифры: парсинг 5000 × 193 мкс ≈ 965 мс,
  ipc 5000 вызовов при потолке моста ~1000/с ≈ 2.5–5 с. итого холодное открытие **3–5 с**
  на каждом старте. после батча: 150–250 мс десктоп, 400–800 мс телефон (io-bound)
- срок: **одна неделя**. merge, поиск в расте, backup-zip в неделю не влезают — вынесены
- сначала замеры (день 0), потом код. без таблицы 100/1000/5000 не начинаем
- неизвестная величина, которую меряем в день 0: сборка индекса orama на 5000. если >500 мс —
  это фаза 2 после недели, в недельный бюджет не влезает
