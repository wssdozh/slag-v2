# integrity: манифест-эталон + гигиена хранилища

- **цель**: у хранилища есть эталон (манифест с хешами по заметке/папке/корню), по которому
  устройство за один проход понимает, что разошлось, и умеет точечно подтянуть недостающее;
  плюс отдельный проход «чистка», который убирает дубли, сирот и мусор в метаданных.
- **трогаем**: `src/lib/vault/integrity/**` (новое), `src/lib/storage/**` (манифест в `state.json`,
  применение фиксов), `src/lib/sync/**` (манифест как канал + точечный pull), `scripts/vault-doctor.mjs`,
  экран настроек «Проверка и чистка», релей `wssdozh/slag-relay` (хранение манифеста комнаты).
- **не трогаем**: формат `.md` и frontmatter (люди читают файлы руками и Obsidian), автоудаление
  заметок по факту отсутствия в манифесте (ровно этот урок стоил 84 файлов 2026-11-18),
  CRDT/LWW-порядок (серверный `syncId` остаётся), вложения целиком не перехешируем на каждый пуш.
- **готово когда**: `npm run vault:doctor` на текущем пк печатает 2 дубля, 9 фантомных папок и
  78 расхождений path↔frontmatter; после `--apply` файлов 91→89, папки сходятся с ноутом,
  повторный прогон даёт ноль находок; `npm run check` зелёный; юнит-тесты манифеста и сканеров
  под `node --test`.
- **уже выяснили**:
  - `computeStateRootHash` (`src/lib/sync/crypto.ts`) считает корень по `id:updatedAt`, то есть по
    меткам времени, а не по содержимому. Для «единой правды» этого мало: одинаковый `updatedAt`
    при разном тексте даёт одинаковый корень.
  - `sentHashes` в `localBookkeeping` уже хранит sha256 каждого элемента — это готовый лист манифеста,
    просто он локальный и ни с чем не сверяется.
  - удаление по вычитанию (`syncedIds` минус текущий список) убрано в `ac18306`; любой новый код,
    который выводит «удалено» из отсутствия, повторяет ту же катастрофу.
  - в `state.json` уже есть секция `sync` (леджер, который переживает вайп), туда же логично класть
    `integrity`.
  - папки в UI строятся из каталогов (`folderSource.folderMetaFor`), поэтому фантомы в `state.json`
    невидимы, но продолжают летать в синк.
  - **сверка не идёт по заметкам.** норма = один корневой хеш (64 символа); спуск в папку — только
    если разошёлся её хеш; в листья — только если разошлась папка. манифест двухслойный: оглавление
    (корень + папки, ~1–2 КБ) ездит всегда, листья — по требованию для разошедшейся ветки.
  - **манифест не пересобирается.** запись заметки обновляет лист и пересчитывает два хеша
    (папка + корень). полный пересчёт — только для «грязных» файлов, и грязность определяется по
    `(path, mtime, size)` из листинга каталога, который мы и так делаем на старте. совпали метаданные
    — файл не читается вообще (приём syncthing/rsync: метаданные первыми, байты по требованию).
  - замер из кода: sha256 всех заметок — 11 мс на 50, 182 мс на 5000. значит даже полный scrub
    дешёвый, но он и не нужен в обычном цикле: это кнопка или ночной прогон раз в неделю.

## P1 сделано (2026-11-19)

`vault-doctor` на реальном хранилище пк: было 91 заметка / 22 каталога / 30 записей в `state.json`,
стало **89 / 21 / 21**, находок high и medium — ноль. В корзину чистки ушли 2 дубля, 58 файлов
встали в свои папки, 9 призрачных записей выпали, один безымянный пустой каталог удалён.

### что выяснилось по ходу

- корень 18.11: бандл `bnd_4e8273d7` от третьего устройства `slag-c090-e67a` (не пк и не ноут)
  импортировался как «1 item», и с диска уехали 58 + 26 = **84 файла** — на обеих машинах.
  дальше девять папок удалили подряд («items re-routed to Inbox»), а вернувшиеся заметки легли
  в `Входящие` с чужим frontmatter. отсюда 78 файлов не на своих местах;
- «78 расхождений» из плана — это 58 реальных `path-mismatch` плюс 20 честных заметок,
  которые и должны лежать во «Входящих»;
- пустая папка **с именем** в `state.json` — это решение человека, а не мусор. сканер теперь
  такие не трогает (`Проекты/Идеи`, `Будущее/Хотелки` и т.п. остались);
- два пространства путей: заметка относительна `notes/`, корзина и `.trash/.hygiene` — корня
  хранилища. резолвинг в одном месте (`absoluteIn`), иначе переносы ищут файлы не там;
- пустой каталог снимается `rmdirSync`; `rmSync` с `recursive: false` на Windows даёт `EISDIR`;
- файл, у которого на месте назначения уже что-то есть, **не** переносится с суффиксом:
  суффикс порождает новый дубль, а не убирает старый;
- на ноуте остались `Архив` и `Личное/Контент` — это расхождение синка, а не грязь:
  чинится не сканером, а тем, что папку либо создают на пк, либо удаляют на ноуте;
- 67 неиспользуемых вложений (`Pasted image …` из Obsidian) — `manual`, решает человек.

### процесс

- воркеры, которым передали `cwd`, всё равно писали в основной каталог: `write()` с абсолютными
  путями. после каждого воркера проверять `git -C <root> status --short` и забирать файлы руками;
- чужую незакоммиченную работу, найденную в стволе, не выбрасывать: копия в
  `.tmp/wip-modals-footer-2026-11-19/`, ствол возвращён к `HEAD`;
- `npm run check` падает на файле с BOM: PowerShell `Set-Content -Encoding UTF8` ставит его молча.

## P2–P6 сделано (2026-11-19, вторая волна)

- `fingerprint.ts` + `manifest.ts`: канонический json, sha256/HMAC, три уровня (лист → папка → корень),
  `compare` даёт `DriftReport`. 11 тестов.
- `snapshot.ts` + `integrityReader.ts`: снимок хранилища поверх `VaultReader`, приложение подставляет
  таури-адаптер, тесты — фейковый ридер.
- `integrityStore.ts`: кодек + io, индекс в `vaults/<v>/.integrity/index.json`, листья рядом.
- `manifestChannel.ts`: провод (версия, лимит 128 КБ, строгий разбор, диф без листьев). 19 тестов.
- `integrityService.ts` + `useIntegrity` + `IntegrityPanel`: вкладка «Хранилище» → «состояние»,
  «Сверить», «Почистить» с переключателем «только отчёт».
- `docs/CODE_MAP.md` перегенерён, AGENTS.md знает про `integrity/`, `vault-doctor` и новую задачу.

### что оказалось не так

- **живой `state.json` лежит в корне хранилища**, а не в `notes/`. Я мерила и правила легаси-копию,
  из-за чего первый отчёт врал: фантомов было не 9, а **37**. Починено в `vault-snapshot.mjs`
  и `vault-doctor.mjs`, легаси-файл возвращён как был.
- снимок **не должен** схлопывать дубли по id: иначе сканеру `duplicate-id` нечего находить
  (старый `buildSnapshot` это делал, плюс склеивал заметки с пустым id в одну).
- два воркера из пяти снова писали абсолютными путями в основную копию; их файлы забраны,
  ошибки починены руками (импорты на уровень выше, `IntegrityIndex` не был импортирован,
  `readFile(path, 'utf8')` вместо `readTextFile`, `copyFile` с `baseDir` вместо `fromPathBaseDir`).
- `rm` для пустого каталога на Windows даёт `EISDIR` — нужен `rmdirSync`.
- нативный `<input type="checkbox">` вылезал из темы; заменён кнопкой-переключателем на токенах.
