# /clear в телеграме: сбросить тред ассистента

- **цель**: команда `/clear` в боте забывает разговор, и следующая реплика снова звучит с чистого листа
- **трогаем**: `relay/server.py` (команда + кадр), `relay/test_notifications.py`,
  `src/lib/sync/transport.ts`, `src/lib/sync/syncEngine.ts`,
  `src/lib/notify/assistant.ts`, `src/context/hooks/useNotifyArm.ts`
- **не трогаем**: UI настроек и модалки — команда живёт в боте, приложение только исполняет
- **готово когда**: `python -m pytest relay/` зелёный, `npm run check` в 0 предупреждений, `npm run build` проходит,
  на телефоне `/clear` отвечает «забыл» и следующий вопрос уже не тянет старый контекст
- **уже выяснили**: история треда — это `localStorage` на самом устройстве (`slag_tg_history_<vaultId>`), релей её
  не видит и стереть не может, поэтому `/clear` — это релей → кадр `assistant_clear` всем живым сокетам хранилища;
  устройств в сети нет — честный отказ, а не «очищено»

---

## после работы

- оказалось: `[[название]]` как настоящей ссылкой в телеграме не сделать. Проверено на живом боте:
  `<a href="slag://note?title=…">` API принимает (`ok: true`), но возвращает `entities: None` — сущность
  выбрасывается молча. Живёт только http(s): `mailto` и `tg://user` тоже срезаются.
  Поэтому путь один: `[[название]]` → страница-переходник на самом релее (`/n?title=…`) → кнопка → `slag://`
  → приложение. Схему регистрируем на десктопе (`reg add` в HKCU / `.desktop` + `xdg-mime`) и на андроиде
  (intent-filter в манифесте).
- `/clear` работает на всех живых устройствах хранилища сразу: тред локальный у каждого, «устройство не в сети»
  — честный отказ, а не тихое «очищено».
- осталось: пункт «ссылки в телеге» живёт отдельной задачей; в `/help` добавить упоминание, что кнопка под
  ответом применяет действие (когда приедут инлайн-кнопки).
