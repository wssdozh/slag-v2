### что осталось открытым

- ui freshness после внешнего mcp: подтверждено отсутствие безопасного rescan/watcher; **не исправлено**. нужен read-only rescan, который не пишет bootstrap cache обратно на диск, отклоняет частичные сканирования и защищён от pending local writes и смены vault. focus-only не обещает live update активного окна; native watcher требует cargo feature/capability и отдельной native проверки. не подменяем эту задачу опасным polling.
- android sync/device: adb найден, но `adb devices` пуст. проверка на реальном устройстве не выполнена.
- исходное пользовательское исчезновение поиска нельзя на 100% связать со stale-index только по скриншоту; исправлен реально воспроизведённый общий дефект.
- legacy одинаковые tokens не кодируют намеренный повтор конкретного файла среди одноимённых; порядок используется для восстановления, явные id/path однозначны.
- ownership черновика runtime-only; после reload неизвестный slot консервативно не удаляется. saveItem остаётся синхронным существующим контрактом, disk flush не доказан.
- расширенная search/assistant проверка у агента: 10 passed / 1 failed — API-error banner для «Привет» не появляется из-за локального fallback. этот сценарий не исправляли.

никакой merge/push/установки приложения пока не выполнено.

### подтверждённые расследованием дефекты (тесты и ревью ещё идут)

- поиск: общий Orama индекс мог остаться построенным по чужому подмножеству записей; поиск по актуальному полному набору его не обновлял. регрессионный тест агента воспроизвёл пустую выдачу до фикса.
- вложения: два разных файла имеют одинаковое имя image.webp; legacy-ссылки по имени разрешаются в первый файл. дополнительно карточка отбрасывает из галереи все файлы с совпадающим именем. фикс проектируется через общий resolver и стабильные id/path, без изменения модели.
- mcp: recurrence/duration чтение уже поддержано, запись save_note не принимает их. опаснее: defaults при частичном update могут превратить задачу в note и сменить папку. исправление должно сохранять omitted fields и defaults только для создания.
- черновик: сравнивается финальный изменённый текст с исходным черновиком, а папка назначения путается с владельцем. принято решение фиксировать внутренний snapshot владельца при раскрытии, очищать только совпадающий snapshot после успешной записи; expand/cancel/crash не должны терять данные.
