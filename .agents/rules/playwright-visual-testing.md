# Визуальное Тестирование и Скриншот-Аудит (Playwright + read_image)

> Стандарт сквозного тестирования пользовательского интерфейса, выявления сползания верстки (Layout Shifting) и визуальных дефектов.

---

## 1. Концепция визуальной верификации

В веб-приложениях зеленый статус функционального теста не гарантирует визуальную корректность. Элемент может присутствовать в DOM, но при этом накладываться на соседний блок, обрезаться контейнером или ломать сетку.

**Обязательное правило**: любые изменения в верстке, компоновке панелей или стилях карточек проверяются связкой **Playwright Screenshot + агентский инструмент `read_image`**.

---

## 2. Команды запуска и захват скриншотов

### 2.1. Запуск E2E тестов
```bash
npx playwright test
```

### 2.2. Захват скриншотов в коде теста Playwright
1. **Полный скриншот рабочей области (Full Page)**:
   ```typescript
   await page.screenshot({
     path: 'test-results/screenshots/full-feed.png',
     fullPage: true,
   });
   ```
2. **Изолированный скриншот компонента / карточки**:
   ```typescript
   const card = page.locator('#item-demo_task_1');
   await card.screenshot({
     path: 'test-results/screenshots/task-card.png',
   });
   ```
3. **Скриншот открытого модального окна или Lightbox**:
   ```typescript
   const modal = page.locator('.fixed.z-50');
   await modal.screenshot({
     path: 'test-results/screenshots/modal-overlay.png',
   });
   ```

## 3. Протокол аудита через `read_image`

После создания скриншота агент обязан вызвать инструмент `read_image` с путем к файлу:
```text
read_image({ file_path: "test-results/screenshots/full-feed.png" })
```

### Чек-лист проверки скриншота на дефекты:
1. **Сползание элементов и переполнение (Layout Shifting & Overflow)**:
   - Отсутствие нежелательного горизонтального скроллбара внизу окна или внутри карточек.
   - Элементы одной строки строго выровнены по базовой линии (`items-center` / `baseline`).
   - Панели сайдбара и инфо-панели не сжимают центральную ленту уже минимальной ширины (min-w-0).
2. **Обрезание текста и наложение (Clipping & Collision)**:
   - Текст не залезает на соседние кнопки, счетчики или иконки.
   - Длинные строки корректно уходят в многоточие (`truncate` / `line-clamp-3`).
   - Иконки не плющатся при недостатке места (наличие `shrink-0`).
3. **Соблюдение дизайн-кода Linear & Vercel**:
   - **Нет рамок фокуса**: отсутствие синих или белых жирных обводок `outline` / `ring` вокруг инпутов и кнопок.
   - **Нет чипсов на чипсе**: текст типа записи («Таска», «Статья») отображается без цветных фоновых подложек поверх карточки.
   - **Нет изогнутых скобок**: отсутствие комбинаций `border-l-*` со скруглением углов контейнера `rounded-*`. Цитаты и ответы имеют замкнутый контур 1px или прямой разделитель.
   - **Фон и контраст**: глубокий монохром (`#08090a`, `#141417`), текст `text-zinc-100` и `text-zinc-400` легко читается без напряжения.
4. **Оверлеи и модальные окна**:
   - Затемнение фона (`backdrop-blur-xl bg-black/80`) равномерно перекрывает нижние слои.
   - Модальное окно центрировано, не вылезает за пределы видимой области экрана.

---

## 4. Протокол устранения визуальных дефектов

Если при просмотре скриншота через `read_image` обнаружен дефект:
1. Зафиксировать конкретное несоответствие (например: *«Иконка скрепки в композере накладывается на поле ввода при ширине 320px»*).
2. Найти CSS-класс или разметку в соответствующем TSX файле.
3. Исправить разметку (добавить `shrink-0`, скорректировать `gap`, `padding` или `min-w`).
4. Повторно запустить тест Playwright, сформировать новый скриншот.
5. Повторно вызвать `read_image` и убедиться в устранении дефекта.
