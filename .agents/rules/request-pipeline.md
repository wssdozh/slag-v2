# Четырехэтапный Пайплайн Запросов

Регламент выполнения задач: от анализа до скриншот-аудита.

---

## 1. Этап 1: Изучение (Reconnaissance)
1. Найти затронутые файлы через `glob` и `grep`.
2. Проверить типы в `src/types/index.ts`, состояние в `src/context/AppContext.tsx` и методы в `src/lib/storage/`.
3. Переиспользовать существующие утилиты и компоненты. Не спрашивать пользователя о фактах, доступных в кодовой базе.

---

## 2. Этап 2: Планировка (Gate ≥ 90%)
1. Зафиксировать: цель, границы изменений, контракты данных и критерии приемки.
2. Не писать код при уверенности ниже 90%.
3. При неопределенности задать вопрос через `ask_user_question`:
   - 1 вопрос за шаг.
   - 2–4 структурированных варианта с инженерными компромиссами.
   - Рекомендуемый вариант первым: `(Рекомендуется)`.

---

## 3. Этап 3: Реализация (Ponytail & Root-Cause)
1. **Лестница Ponytail**: YAGNI ➔ утилиты `src/lib/` ➔ нативный JS/TS/Web API ➔ установленный пакет ➔ 1 строка ➔ минимальный код.
2. **Root-Cause Fix**: Запрещены `?.`, пустые `catch`, `setTimeout(..., 100)`. Чинить причину в источнике данных.
3. Доводить задачу до конца автономно без пауз на согласование очевидных шагов.

---

## 4. Этап 4: Тестирование и DoD
1. `npm run lint` — 0 warnings, 0 errors (`oxlint`).
2. `npm run build` — чистая сборка Vite и `tsc -b`.
3. `npx playwright test` — 100% тестов пройдены.
4. **Скриншот-верификация (UI и логика действий)**:
   - Снять скриншот работы фичи/действия: `await page.screenshot({ path: 'test-results/screenshots/<name>.png', fullPage: true })`.
   - Просмотреть через `read_image`, проверить корректность работы логики и верстки.
   - **Обязательно показать скриншот пользователю в ответе**: `![Результат](<test-results/screenshots/<name>.png>)`.
5. Коммит Conventional Commits на английском языке.
