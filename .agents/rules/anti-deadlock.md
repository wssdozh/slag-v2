# Защита от Зацикливания и Поиск Первопричин

Устранение первопричин сбоев и предотвращение накопления костылей.

---

## 1. Лестница простоты Ponytail
Перед написанием кода проверить альтернативы снизу вверх:
1. `Нужно ли это вообще?` (YAGNI).
2. `Есть ли уже в проекте?` (Использовать `src/lib/` и `AppContext`).
3. `Решает ли стандартный JS / TS / Web API?`
4. `Решает ли установленный пакет?` (`lucide-react`, `@orama/orama`).
5. `Можно ли решить в одну строку?`
6. `Минимальный достаточный код.`

Осознанные упрощения маркировать: `// ponytail: <лимит и путь решения>`.

---

## 2. Запрещенные костыли vs Первопричина

| Запрещенный костыль | В чем первопричина | Правильное решение |
|---|---|---|
| `item?.title?.slice()` по компонентам | Неполная инициализация или кривой парсинг | Исправить фабрику или парсер в `src/lib/storage/` |
| Пустой `try { ... } catch {}` | Невалидные входные данные | Валидировать данные до вызова |
| `setTimeout(..., 100)` для стейта | Рассинхрон жизненного цикла React | Детерминированные колбэки, чистые эффекты |
| Флаги `isPatchApplied`, `isFixRunning` | Дублирование подписок или эффектов | Исправить массив зависимостей хука |

---

## 3. Правило 3 попыток (Anti-Loop)
1. **Попытка 1**: Прочитать точный лог ошибки и номер строки. Устранить первопричину.
2. **Попытка 2**: Проверить типы в `src/types/index.ts`, зависимости и окружение.
3. **Попытка 3**: Если ошибка сохраняется — **остановиться**.
   - Привести лог ошибки.
   - Запросить решение через `ask_user_question` с 2–4 структурированными вариантами.
