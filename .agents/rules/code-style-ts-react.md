# Стандарты Кода: TypeScript, React 19 и Oxlint

Инженерные правила разработки на TypeScript и React 19.

---

## 1. Архитектура React 19
1. **Fast Refresh**: Файл компонента экспортирует только React-компоненты. Константы, утилиты и конфигурации иконок выносить в отдельные модули (например, `folderIcons.ts`).
2. **Чистые эффекты (`useEffect`)**:
   - Запрещен синхронный вызов `setState` внутри `useEffect`. Переносить установку стейта в обработчики событий или вычислять значения при рендере.
   - Массив зависимостей обязан содержать все используемые переменные. Не отключать линтер.
   - Каждый `addEventListener` обязан иметь парный `removeEventListener` в функции очистки.
3. **Мемоизация**: Оборачивать в `useCallback` методы, передаваемые в глубокие дочерние компоненты или в глобальные слушатели.
4. **Изоляция Tauri (MVP)**: Запрещено импортировать `@tauri-apps/*` в UI-компоненты (`src/components/`) и UI-хуки. View только рендерит стейт и вызывает экшены `AppContext`. Вся работа с нативным API и FS — в `src/lib/storage.ts`.

---

## 2. TypeScript
1. **Строгая типизация**: Запрещен тип `any`. Использовать `unknown` с последующим сужением типа.
2. **Централизация типов**: Доменные интерфейсы (`SlagItem`, `FolderMeta`, `VaultMeta`, `SlagAttachment`) объявлять в `src/types/index.ts`. Не дублировать типы локально.
3. **Именование (Entity-First)**: Имя переменной идет от сущности к свойству (`activeItemId`, `currentFolder`). Булевы переменные — с префиксами `is`, `has`, `can` (`isOpen`, `hasAttachments`).

---

## 3. Tailwind CSS v4
1. **Порядок классов**: Позиционирование ➔ Flex/Grid ➔ Размеры и геометрия ➔ Типографика ➔ Цвета и фон ➔ Интерактивные состояния (`hover:`, `active:`).
2. **Без инлайн-стилей**: Стили оформляются классами Tailwind. Инлайн-стили допустимы только для вычисленной геометрии (`style={{ width: `${width}px` }}`).

---

## 4. Контроль качества (Oxlint)
- Команда проверки: `npm run lint`.
- Требование: **0 warnings, 0 errors**. Предупреждения блокируют сдачу задачи.
