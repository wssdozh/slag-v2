# Стандарты Кода: TypeScript, React 19 и Oxlint

> Инженерные правила написания чистого кода на TypeScript и React 19.  
> Исключают утечки памяти, каскадные рендеры и поломки Fast Refresh.

---

## 1. Архитектура компонентов React 19

1. **Правило Fast Refresh**:
   - Файл компонента обязан экспортировать **только React-компоненты**.
   - Экспорт констант, утилит или конфигураций иконок из файлов компонентов запрещен (выносить в отдельные модули, например `folderIcons.ts`).
2. **Чистые эффекты (`useEffect`)**:
   - **Запрет синхронного вызова `setState` внутри `useEffect`**:
     ```typescript
     // ЗАПРЕЩЕНО (вызывает каскадный рендер и варнинг oxlint):
     useEffect(() => {
       if (isOpen) {
         setLoading(true);
         fetchData();
       }
     }, [isOpen]);

     // ПРАВИЛЬНО:
     // Переносить установку стейта в обработчик открытия или вычислять в рендере
     ```
   - Массив зависимостей эффекта обязан содержать **все используемые переменные**. Не скрывать зависимости отключением проверок.
3. **Мемоизация колбэков**:
   - Все методы, передаваемые в глубокие дочерние компоненты или регистрируемые в глобальных слушателях событий, оборачивать в `useCallback`.
4. **Очистка слушателей событий**:
   - Каждый `addEventListener` обязан иметь парный `removeEventListener` в функции очистки `useEffect`.
5. **Изоляция нативного слоя (Tauri-Free View / Паттерн MVP)**:
   - Запрещено импортировать `@tauri-apps/*` в компоненты (`src/components/`) и UI-хуки.
   - Компоненты (View) только отрисовывают стейт и вызывают экшены `AppContext` (Presenter). Вся работа с нативным API и файловой системой изолирована в `src/lib/storage.ts` (Model).

---

## 2. Стандарты TypeScript

1. **Строгая типизация без `any`**:
   - Использование типа `any` запрещено. При неизвестной структуре использовать `unknown` с последующим сужением типа.
2. **Централизация доменных интерфейсов**:
   - Все ключевые модели (`SlagItem`, `FolderMeta`, `VaultMeta`, `SlagAttachment`) определяются в `src/types/index.ts`.
   - Запрещено дублировать определения типов локально внутри компонентов.
3. **Именование сущностей (Entity-First)**:
   - Имя переменной идет от сущности к свойству: `activeItemId`, `currentFolder`, `isRightPanelOpen`.
   - Булевы переменные имеют префиксы `is`, `has`, `can` (`isOpen`, `hasAttachments`, `canSubmit`).

## 3. Верстка и Tailwind CSS v4

1. **Порядок классов Tailwind**:
   - Позиционирование (`absolute`, `relative`, `fixed`, `z-50`).
   - Блочная модель и Flex/Grid (`flex`, `grid`, `items-center`, `justify-between`).
   - Размеры и геометрия (`w-full`, `h-12`, `p-3`, `gap-2`, `rounded-xl`).
   - Типографика (`text-xs`, `font-mono`, `text-zinc-100`).
   - Цвета и фон (`bg-[#141417]`, `border`, `border-white/[0.05]`).
   - Интерактивные состояния (`hover:bg-[#161619]`, `transition-colors`, `active:scale-[0.98]`).
2. **Запрет инлайн-стилей для тем**:
   - Цвета и стили оформляются через классы Tailwind, за исключением динамических геометрических параметров (например, вычисленная ширина панелей `style={{ width: `${width}px` }}`).

## 4. Контроль качества (Oxlint)

Команда `npm run lint` запускает `oxlint`.
- Любое предупреждение линтера блокирует выполнение задачи.
- Код коммитится только при вердикте: `Found 0 warnings and 0 errors`.
