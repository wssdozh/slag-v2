# Регламент работы агента с MCP хранилища SLAG

Когда в окружении подключен MCP-сервер `slag`, агент обязан соблюдать следующие правила взаимодействия с базой знаний и задачами пользователя.

---

## 1. Принцип проверки фактов (Grounding First)

1. Перед ответом на вопросы о планах, прошлых решениях или контенте пользователя — **всегда вызывать `search_notes` или `get_note`**. Не домысливать и не придумывать названия заметок.
2. При поиске ориентироваться на ключевые слова, сужая поиск параметром `folder`, если контекст известен.

---

## 2. Политика создания и изменения заметок (Taxonomy First)

1. **Проверка тегов**: перед добавлением новых тегов в аргумент `tags` инструмента `save_note`, вызвать `list_tags`. Использовать уже существующие в хранилище теги во избежание дублирования синонимов.
2. **Выбор папки**: перед созданием новой структуры вызвать `list_folders`. Сохранять материалы строго по назначению папок. Не создавать новые папки без прямой необходимости.
3. **Обновление записей**: если заметка уже существует, передавать её `id` в `save_note`. Использовать `appendContent` для добавления записей в конец логов или списков без перезаписи заголовков и структуры.

---

## 3. Управление задачами

1. Для получения задач на сегодня вызывать `list_tasks(view="today")`.
2. При закрытии дел вызывать `toggle_task(id="...", status="done")`.
3. Задачи с дедлайнами создавать через `save_note` с `type="task"` и форматом `dueDate="YYYY-MM-DD"`.

---

## 4. Безопасность данных (Obsidian Local-First)

1. Инструмент `delete_note` перемещает файлы в каталог `.trash/`. Напрямую файлы с диска не стираются.
2. Не перезаписывать тело заметки пустым текстом. При правках сохранять структуру YAML frontmatter.
