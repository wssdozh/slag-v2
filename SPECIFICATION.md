# ТЕХНИЧЕСКАЯ СПЕЦИФИКАЦИЯ: СИСТЕМА ЗАМЕТОК SLAG v2

> **Версия:** 2.0.0  
> **Статус:** Утверждено  
> **Стек:** Tauri v2, React 19, TypeScript, Tailwind CSS v4, Orama Search Engine, Gemini 2.0 Flash API, Tiptap / ProseMirror  
> **Дизайн-код:** Linear & Vercel Minimal Dark, Apple Fluid Interface, Local-First Obsidian Architecture  

---

## 1. Концепция и философия продукта

### 1.1. Основная идея
**SLAG v2** — персональная, локальная (Local-First) система для ведения заметок, статей и задач, спроектированная так, чтобы быть **«понятной даже долбаёбу»**:
1. **Нулевой порог входа**: нет сложных баз данных, запутанных иерархий настроек, перегруженных тулбаров и баннеров обучения. Интерфейс интуитивен с первой секунды.
2. **Формат мессенджера (Telegram Monologue)**: ввод заметок ощущается как быстрый чат с самим собой в «Избранном» Telegram — написал мысль, нажал `Enter`, и она мгновенно зафиксирована в ленте.
3. **Чистые данные (Obsidian-совместимость)**: данные хранятся прямо на диске пользователя в виде обычных `.md` файлов с YAML Frontmatter. Приложение не запирает пользователя в проприетарных форматах.
4. **Тихий ИИ без мусора (Zero-Slop Gemini Flash)**: ИИ не генерирует вежливых бессмысленных ответов («Здравствуйте! Вот теги для вас...»). Он работает за доли секунды под капотом: анализирует имеющуюся таксономию тегов, проставляет точные метаданные и помогает распределять неразобранное по папкам.

В приложении **категорически запрещены яркие разноцветные градиенты, радужные плашки и кислотные цвета**. Интерфейс строится на тонких градациях черного и темно-серого, обеспечивая отдых для глаз при многочасовой работе.

### 2.2. Правило «Никаких чипсов на чипсе»
- **Строгий запрет**: запрещено размещать внутренние плашки со сплошным фоном (chips / badges) поверх карточек, которые уже имеют собственный фоновый цвет.
- **Решение**: тип записи («Таска», «Статья»), статус и время чтения отображаются **чистым моноширинным текстом** без фоновых плашек:
  ```html
  <!-- ПРАВИЛЬНО: чистый типографический акцент -->
  <span class="text-[11px] font-mono text-amber-400/90 font-medium">Таска</span>
  
  <!-- ЗАПРЕЩЕНО: грязь и перегруз -->
  <span class="bg-amber-500/20 px-2 py-0.5 rounded-full text-amber-300">Таска</span>
  ```

### 2.3. Категорический запрет на боковые бордеры со скруглениями (изогнутые скобки)
- **Строжайший запрет**: категорически запрещено сочетание односторонних боковых бордеров (`border-l-*`, `border-r-*`) с любыми скруглениями углов контейнера (`rounded-*`). В браузерном рендере CSS это приводит к уродливому загибанию линии по радиусу углов, создавая эффект изогнутой скобки: `( Текст`.
- **Решение для цитат, плашек ответов (Reply) и контекстных блоков**:
  - Использовать **равномерный замкнутый тонкий контур**: `border border-white/[0.06] rounded-lg` и приглушенный фон `bg-white/[0.03]`.
  - Либо плоский фон без границ вовсе.
  - Если по логике дизайна требуется вертикальная акцентная линия-разделитель — она верстается **исключительно как отдельный прямой прямоугольный элемент** (`<div className="w-0.5 self-stretch bg-zinc-600 rounded-none shrink-0" />`) без каких-либо скруглений на концах.
  - Никаких цветных кричащих полос (синих, ядовитых). Индикация ответа осуществляется минималистичной иконкой `CornerUpLeft` и спокойным моноширинным текстом `text-zinc-400`.

### 2.4. Рамки фокуса и интерактивные состояния
- **Никаких синих/белых рамок фокуса**: для всех `input`, `textarea`, `button` применяется `outline: none; ring: 0`. 
- Индикация фокуса осуществляется только едва заметным повышением яркости границы (`border-white/[0.12]`) или мягким изменением прозрачности фона.

### 2.5. Сетка отступов и радиусы скруглений
- **Базовый шаг отступов**: 4px scale (`4px`, `8px`, `12px`, `16px`, `24px`).
- **Скругления (Border Radius)**:
  - Элементы управления (кнопки, инпуты): `6px` (`rounded-md`).
  - Карточки заметок, превью медиа: `12px` (`rounded-xl`).
  - Модальные окна, остров композера, полноэкранный редактор: `16px` (`rounded-2xl`).
- Элементы, находящиеся в одной строке, строго выравниваются по единой базовой линии ради компенсации пространства.

### 2.6. Кастомные элементы: Скроллбар, Тосты, Слайдеры
- **Скроллбар**: ультра-тонкий (4px), полупрозрачный трек `transparent`, ползунок `rgba(255, 255, 255, 0.12)` со скруглением `9999px`. Появляется только при активном скролле.
- **Тосты (Toasts)**: ненавязчивые всплывающие сообщения в правом нижнем углу экрана (`#18181b`, граница `1px rgba(255,255,255,0.08)`), автоматически исчезающие через 2.5 секунды.
- **Слайдеры**: темный трек `2px`, минималистичный круглый ползунок без обводок.

## 3. Физика интерфейса и управление слоями (Apple Design)

### 3.1. Мгновенный отклик (Zero Latency)
- Реакция на нажатия и выделения срабатывает на событие `pointerdown`, а не на отпускание клавиши мыши `click`.
- При нажатии на кнопку масштаб мгновенно уменьшается до `scale(0.97)` с физическим возвратом.

### 3.2. Прерываемые анимации (Interruptible Springs)
- Никаких затяжных или блокирующих CSS-анимаций.
- Все переходы модалок, шторок и выпадающих меню используют критически затухающие пружины:
  - `damping: 1.0` (критическое затухание без лишнего дребезга и клоунады).
  - `response: 0.3–0.35s` (быстрое, органичное появление).
- Пользователь может в любой момент прервать анимацию закрытия или открытия повторным кликом или жестом без скачков и рывков.

### 3.3. Иерархический стек закрытия слоёв (LIFO Dismissal Stack)
Все перекрывающие элементы интерфейса регистрируются в едином менеджере слоев:
```
[Слой 1] Полноэкранный редактор / Модалка настроек
  ↳ [Слой 2] Диалоговое окно (например, создание подпапки)
    ↳ [Слой 3] Выпадающий селектор / контекстное меню
```
- **Правило клика мимо и клавиши `Escape`**: закрывается **строго последний (самый верхний) слой**. Если открыто контекстное меню поверх модалки — клик мимо закрывает *только контекстное меню*, оставляя модалку открытой. Повторный клик закрывает модалку.

### 3.4. Единое контекстное меню (ПКМ и кнопка «три точки»)
- **Полная ликвидация дублирующих меню**: в интерфейсе полностью вырезаны локальные всплывающие списки на карточках. И правый клик (ПКМ) по карточке, и нажатие на кнопку «три точки» (`MoreVertical`) вызывают **одно и то же единое, отполированное контекстное меню**.
- **Стилизация Linear**: `bg-[#121215]/95`, `backdrop-blur-xl`, `border border-white/[0.08]`, `w-56`, `rounded-xl`, моноширинные бейджи горячих клавиш справа.
- **Действия для карточки заметки**:
  - `Ответить` (`R`, иконка `CornerUpLeft`) — прикрепляет цитату над композером.
  - `Фокус-редактор` (`⌘E`, иконка `Maximize2`) — открывает полноэкранный редактор.
  - `Закрепить / Открепить` (`P`, иконка `Pin`) — фиксация записи вверху ленты.
  - `Сменить тип` (иконка `Repeat`) — быстрая конвертация «на лету» в Таску / Заметку / Статью.
  - `Переместить в папку` (иконка `FolderInput`) — выпадающий скроллируемый список всех папок с отметкой текущей.
  - `Копировать [[линк]]` (`⌘L`, иконка `Link2`) — копирует вики-ссылку формата Obsidian.
  - `Копировать текст` (`⌘C`, иконка `Copy`) — копирует чистый Markdown контента.
  - `Удалить` (`⌫`, иконка `Trash2`, `text-rose-400`) — удаление записи с тостом подтверждения.
- **Действия по папке в сайдбаре**: Создать подпапку, Изменить иконку и описание, Удалить папку.
- **Действия по пустому месту ленты**: Новая заметка, Новая таска, Новая статья, Глобальный поиск (`⌘K`).

## 4. Архитектура данных: Obsidian-совместимое локальное хранилище

### 4.1. Физическая структура на диске
Хранилище представляет собой обычную директорию на жестком диске или в памяти устройства:

```
MyVault/
├── .attachments/                      # Вложенные медиа (картинки, войсы, квадраты)
│   ├── att_1716034100_screen.png
│   ├── voice_1716034200.webm
│   └── video_1716034300.webm
├── .slag/
│   ├── folders.json                   # Метаданные папок (иконки, описания для ИИ)
│   └── config.json                    # Настройки интерфейса и ИИ
├── Входящие/
│   ├── Идея для стартапа.md
│   └── Купить кофе.md
├── Проекты/
│   ├── SLAG v2/
│   │   └── Архитектура ядра.md
│   └── Дизайн/
│       └── Референсы Linear.md
└── Личное/
    └── Заметки о книгах.md
```

### 4.2. Именование файлов `.md`
- Имя файла генерируется **по названию заметки**: `Заголовок.md`.
- Запрещенные операционной системой символы (`\ / : * ? " < > |`) автоматически экранируются/удаляются.
- При обнаружении дубликата имени файла автоматически добавляется суффикс ` 1.md`, ` 2.md`.
- При переименовании заголовка в фокус-редакторе файл на диске безопасно переименовывается без потери связей.

### 4.3. Стандарт YAML Frontmatter
Каждый `.md` файл начинается с валидного frontmatter блока, гарантирующего 100% совместимость с Obsidian и другими редакторами:

```markdown
---
id: note_1716034000_abc
type: task                  # note | article | task
title: Реализовать ИИ-триаж входящих
created: 1716034000000
updated: 1716034100000
tags:
  - ai
  - gemini
  - productivity
folder: Проекты/SLAG v2
status: in_progress         # todo | in_progress | done (только для task)
priority: high              # none | low | medium | high (только для task)
dueDate: 2025-05-20         # YYYY-MM-DD
reminder: 2025-05-20T10:00:00Z
subtasks:
  - id: st1
    title: Собрать описания всех папок
    completed: true
  - id: st2
    title: Написать промпт для Gemini Flash
    completed: false
readingTime: 2              # минуты (только для article)
summary: Краткая выжимка статьи
replyTo: note_1716033900_xyz # ID заметки, на которую дан ответ
linked:
  - note_1716033500_foo     # Связанные заметки
attachments:
  - id: att_1
    name: screen.png
    type: image
    relativePath: .attachments/att_1_screen.png
---

Здесь находится основной текст заметки в чистом формате Markdown...
```

## 5. Трехуровневая модель контента: Заметка, Статья, Задача

Все три типа записей наследуются от единого интерфейса `SlagItem`:

```typescript
export type SlagItemType = 'note' | 'article' | 'task';

export interface SlagItem {
  id: string;
  type: SlagItemType;
  title: string;
  content: string; // Markdown
  folder: string;  // Относительный путь, например "Входящие" или "Проекты/SLAG"
  tags: string[];
  attachments: SlagAttachment[];
  createdAt: number;
  updatedAt: number;
  isPinned?: boolean;
  isArchived?: boolean;

  // Task-специфичные поля
  status?: 'todo' | 'in_progress' | 'done';
  priority?: 'none' | 'low' | 'medium' | 'high';
  dueDate?: string; // YYYY-MM-DD
  reminder?: string; // ISO DateTime
  recurrence?: string; // iCalendar RFC 5545 recurrence rule
  subtasks?: Array<{ id: string; title: string; completed: boolean }>;

  // Article-специфичные поля
  readingTimeMinutes?: number;
  summary?: string;

  // Связи и ответы
  replyToId?: string;
  linkedItemIds?: string[];
}
```

### 5.1. Заметка (Note)
- **Назначение**: моментальная фиксация мысли, кода, цитаты, голосового сообщения или изображения.
- **Отображение в ленте**: компактный карточный блок с полным текстом Markdown, плеером голосового или видео, превью картинок и списком тегов.

### 5.2. Статья (Article)
- **Назначение**: длинные материалы, лонгриды, конспекты, аналитические статьи и документация.
- **Отображение в ленте**:
  - Автоматическое сворачивание: в ленте отображаются заголовок, бейдж примерного времени чтения (`• 3 мин чтения`), краткая выжимка (если есть) и первые 4–5 строк текста.
  - Кнопка **«Читать полностью»**: плавное раскрытие прямо в ленте или открытие в фокус-редакторе.

### 5.3. Задача (Task)
- **Назначение**: дела, списки покупок, дедлайны проектов с подзадачами.
- **Отображение в ленте**:
  - Иконка статуса (круглый чекбокс: Todo / In Progress / Done). Клик по чекбоксу меняет статус **напрямую в ленте без модалок**.
  - Индикатор приоритета (текстовый: Low / Medium / High).
  - Сворачиваемый интерактивный список подзадач: чекбоксы подзадач кликабельны прямо в карточке стрима. Прогресс-бар выполнения (например, `3/5`).
  - Бейдж дедлайна и времени напоминания (`dueDate`, `reminder`, `recurrence`).
- **Умный ввод дат (Chrono-node NLP & Quick Add)**:
  - Автоматическое распознавание дат и времени из естественной речи (RU/EN) с помощью `chrono-node`.
  - Краевое якорение (Edge Anchoring): анализ только начала (`^...`) или конца (`...$`) строки для защиты от ложных срабатываний.
  - Ghost-чип под полем ввода с возможностью отмены даты в 1 клик (`✕`) или по `Escape`.
  - Сохранение исходного текста: распознанные слова не вырезаются из задачи.
  - Системные уведомления по таймеру через `tauri-plugin-notification` с веб-фоллбеком на `Notification API`. См. [[10_Smart_Dates_and_Reminders]].

## 6. Мульти-представления папки и Telegram-композер

### 6.1. Три режима представления папки
В шапке центральной рабочей области (`FeedHeader`) расположен переключатель представлений:
`[ 📜 Лента | 📋 Канбан | 📅 Календарь ]`

1. **Стрим (Лента / Stream Feed)**:
   - Заметки располагаются в хронологическом порядке: **старые сверху, новые снизу** (как в реальном чате).
   - Плавающие разделители дат («Сегодня», «Вчера», даты).
   - Быстрый инлайн-композер внизу экрана с переключением типов записей, микрофоном и видеоквадратами.
2. **Канбан по ТРИЗ с кастомными столбцами (Kanban Board)**:
   - **Индивидуальные стадии для каждой папки**: жизненный цикл задач настраивается индивидуально для каждой папки в `FolderMeta.kanbanColumns` (например, `Бэклог ➔ В работе ➔ Код-ревью ➔ Релиз`).
   - **Семантический маппинг (`statusMapping`)**: каждый кастомный столбец мапится на `todo`, `in_progress` или `done`, что сохраняет прозрачную синхронизацию с чекбоксами задач в стрим-ленте.
   - **ТРИЗ-разрешение конфликта смешанных сущностей**:
     - Колонка **«Материалы» (Reference Dock)** слева: отображает все `note` и `article` папки в компактном виде, не смешивая их с процессными колонками задач.
     - **Фазовый переход**: перетаскивание заметки из «Материалов» в колонку задач конвертирует её в `task` или связывает через `linkedItemIds`.
     - **Динамичность**: если в папке нет заметок, колонка «Материалы» автоматически схлопывается.
   - **Управление доской**: добавление столбцов кнопкой `+ Столбец`, инлайн-переименование и перетаскивание столбцов за заголовок.
3. **Календарь дедлайнов (Calendar View)**:
   - Сетка месяца/недели с группировкой задач по дедлайну (`dueDate`).
   - Перетаскивание карточки на ячейку дня для мгновенного назначения срока.
   - Боковая шторка «Без срока» (Unscheduled) для быстрого распределения задач.

### 6.2. Остров ввода (Composer Island)
Остров ввода зафиксирован внизу центральной колонки:
- **Авто-высота**: автоматически расширяется по мере ввода текста от 40px до 220px со стильным внутренним скроллом.
- **Горячие клавиши отправки**:
  - `Enter` — **мгновенная отправка** записи в ленту (быстрый поток мыслей).
  - `Shift + Enter` — перенос строки без отправки.
- **Кнопка раскрытия в полноэкранный редактор (`Maximize2`)**: расположена на острове ввода рядом с кнопкой отправки. Клик мгновенно переносит набранный черновик в просторный Focus Editor.
- **Быстрый селектор типа**: переключение между Заметкой, Таской и Статьей одним кликом.
- **Мультимедиа-триггеры**:
  - Кнопка микрофона: переключение в режим записи войса.
  - Кнопка видеокамеры: переключение в режим записи видео-квадрата.
  - Кнопка скрепки: выбор файлов или перетаскивание Drag & Drop.
- **Кнопка умного тегирования (`+Ai Sparkles`)**: ручной запуск генерации тегов до отправки (по желанию).

### 6.3. Ответы (Replies) и внутренняя перелинковка
- В контекстном меню заметки или по кнопке быстрого действия доступна опция **«Ответить»**.
- При выборе ответа над композером появляется аккуратная полоска с цитатой исходной заметки и кнопкой отмены (`X`).
- В готовой карточке заметки отображается ссылка на родительскую запись. Клик по ней плавно скроллит ленту к оригиналу и на 1 секунду подсвечивает карточку мягким свечением (`rgba(255,255,255,0.08)`).

## 7. Мультимедиа-движок

### 7.1. Голосовые сообщения (Audio Waveform)
- Запись аудио через веб-API `MediaRecorder` (`audio/webm;codecs=opus`).
- Отображение аудиоволны с визуализацией амплитуды в реальном времени.
- Встроенный кастомный темный аудиоплеер: кнопка Play/Pause, таймлайн с возможностью перемотки кликом, переключатель скорости воспроизведения (`1.0x`, `1.5x`, `2.0x`).

### 7.2. Видеосообщения («Квадратики» 1:1)
- Вместо привычных Telegram-кружков в SLAG используются **видеосообщения с квадратным соотношением сторон 1:1** со стильными скруглениями углов `12px`.
- Запись с веб-камеры или фронтальной камеры смартфона с квадратной маской видоискателя, таймером записи и индикатором уровня звука.
- Плеер видеоквадратов: воспроизведение прямо внутри ленты, возможность зацикливания, раскрытия на весь экран и скачивания.

### 7.3. Полноэкранный просмотрщик изображений (Lightbox Gallery)
- При клике на любое изображение в ленте или в правой панели открывается оверлей галереи.
- **Навигация**: клавиши `←` (Влево) и `→` (Вправо) позволяют **листать все изображения текущей активной папки**.
- **Интерактив**: зум колесиком мыши, перетаскивание увеличенной картинки, закрытие по `Escape` или клику мимо.

## 8. Сайдбар, дерево папок и гибридный Inbox

### 8.1. Сайдбар и вложенные папки
- Регулируемая ширина сайдбара (по умолчанию 260px, ресайзинг перетаскиванием правой границы).
- Неограниченная иерархия папок и подпапок (пути вида `Проекты/SLAG v2/Frontend`).
- Кастомизация папок:
  - Выбор иконки из библиотеки (Folder, Code, Layers, Bookmark, Briefcase, Sparkles и др.).
  - Поле **«Описание папки»**: текстовое описание предназначения папки на человеческом языке (критически важно для работы ИИ-сортировки).

### 8.2. Гибридный режим папки «Входящие»
Пользователь имеет доступ к трем режимам отображения во «Входящих»:
1. **«Все заметки»**: сквозной стрим абсолютно всех заметок из всех папок хранилища.
2. **«Неразобранные» (по умолчанию)**: только те заметки, которые еще физически находятся в корневой папке `Входящие` и ждут распределения.
3. **«Разобранные»**: заметки, которые уже получили свои тематические папки.

## 9. Правая панель: Инфо-панель папки и ИИ-Копилот

Правая выдвижная панель (`FolderInfoPanel`, ширина по умолчанию 320px) сочетает две функции с переключателем в шапке `[ Инфо | Ассистент ]` (хоткей `⌘J` / `Ctrl+J`):

### 9.1. Режим «Инфо»
- **Заголовок и описание**: отображение названия папки, кастомной иконки и подробного описания (с кнопкой быстрого инлайн-редактирования).
- **Сводная статистика**: общее число заметок, активных задач и статей.
- **Вкладки медиафайлов папки**:
  1. **Медиа**: сетка всех изображений и видеоквадратов папки.
  2. **Аудио**: список всех записанных голосовых сообщений с датами и длительностью.
  3. **Файлы**: список прикрепленных PDF, архивов и документов с отображением размера.
  4. **Ссылки**: автоматически извлеченные из markdown-текстов внешние URL-адреса.
  5. **Теги**: облако всех тегов, используемых в заметках данной папки (клик по тегу мгновенно фильтрует ленту).

### 9.2. Режим «Ассистент» (ИИ-Копилот)
- **Параллельная работа**: доступен одновременно с любым из трех центральных представлений (Стрим, Канбан, Календарь), не перекрывая рабочее полотно (ТРИЗ-разделение в пространстве).
- **Локальный RAG по папке**: ассистент отвечает строго по контексту открытой папки (а во «Входящих» — по всей базе знаний) через вызовы инструментов `search_notes` и `read_note`.
- **Черновики в один клик**: генерация карточек с кнопкой сохранения прямо в хранилище.

## 10. Интеллектуальный ИИ-слой (Gemini Flash)

### 10.1. Требования к ИИ-ассистенту
- **Модель**: `gemini-2.0-flash` (по умолчанию) с временем генерации <400 мс и минимальной стоимостью.
- **Полное отсутствие AI-мусора**: вывод строго в `responseMimeType: "application/json"`. Запрещены вступительные и заключительные фразы.

### 10.2. Индексация таксономии и умное тегирование
Перед вызовом ИИ-модели выполняется индексация всего хранилища:
1. Собирается множество всех уже существующих тегов пользователя (`existingTags`).
2. В системный промпт передается существующий словарь:
   ```
   Правила таксономии:
   1. Существующие теги пользователя: [дизайн, архитектура, react, финансы]
   2. В ПЕРВУЮ ОЧЕРЕДЬ выбери подходящие теги из существующего списка. Не плоди синонимы!
   3. Новый тег создавай ТОЛЬКО если тема принципиально новая.
   4. Верни чистый JSON-массив строк.
   ```
3. **Оффлайн-фолбэк**: при отсутствии API-ключа или интернета работает встроенный быстрый эвристический парсер ключевых слов.

### 10.3. Автоматический AI Triage (сортировка «Входящих»)
- ИИ анализирует неразобранные заметки из папки «Входящие» и сравнивает их контекст с **описаниями папок** (`FolderMeta.description`).
- **Сценарий с подтверждением**:
  1. Пользователь нажимает кнопку **«ИИ-сортировка»** в шапке ленты.
  2. Открывается модальное окно с карточками предложений:
     - Заголовок заметки.
     - Предлагаемая папка назначения.
     - Краткая причина решения ИИ (например: *«Совпадение по теме верстки интерфейса»*).
  3. Пользователь может снять галочки с отдельных пунктов или нажать **«Применить всё»** — файлы физически переносятся в соответствующие директории на диске.

## 11. Поиск и локальная индексация (Orama Engine)

- **Движок**: `@orama/orama` (полностью локальный, легковесный, запущенный в памяти WebAssembly/JS движок поиска).
- **Индексируемые поля**: `id`, `type`, `title`, `content`, `tags`, `folder`.
- **Особенности**:
  - Полнотекстовый поиск BM25 с толерантностью к опечаткам (Fuzzy tolerance = 1).
  - Мгновенная фильтрация по типу (`type: task`, `type: article`, `type: note`) и тегам.
  - Векторные эмбеддинги (Hybrid Search): готовность к подключению векторного поиска через `@orama/plugin-embeddings` или API векторов Gemini.
- **Шорткат**: глобальный вызов командной строки поиска по сочетанию `⌘K` / `Ctrl+K`.

## 12. Механики Drag-and-Drop

1. **Ресайзинг панелей**: плавное перетаскивание границы левого сайдбара и правой панели информации с запоминанием ширины в `localStorage`.
2. **Перемещение заметок**: карточку любой заметки можно захватить мышью и перетащить в любую папку дерева сайдбара.
3. **Dropzone файлов**: перетаскивание файлов (картинок, документов, аудио) с рабочего стола прямо в область ленты или поле композера с автоматическим сохранением в `.attachments/`.
4. **Реорганизация дерева**: перетаскивание папок для вкладывания друг в друга.

Настройки разбиты на строгие тематические вкладки:

## 14. Мобильная адаптация и будущее развитие (Roadmap)

### 14.1. Кроссплатформенность на Tauri v2
- Единая кодовая база на TypeScript / React.
- На мобильных платформах (iOS / Android) вместо трех колонок интерфейс переключается на нативную модель экранов:
  - Нижняя навигационная панель (Входящие, Папки, Поиск, Настройки).
  - Свайп вправо для возврата к списку папок.
  - Полноэкранный фокус-редактор с адаптивной клавиатурой.

### 14.2. E2E-шифрованная синхронизация (Non-Storage Relay & SyncBundle)
- **Принцип сервера-синхронизатора, а не хранилища**: сервер ретрансляции не имеет постоянной базы данных заметок. Он выступает в роли эфемерного брокера зашифрованных дельт (Zero-Knowledge Transient Relay / FIFO Mailbox).
- **Слепые комнаты**: комната релея идентифицируется как `SyncRoomId = HMAC-SHA256(VaultKey, "slag-relay-room-v1")`. Сервер не знает ни ключа, ни содержимого.
- **Пакетная передача дельт (`SyncBundle`)**:
  - Все изменения (новые/отредактированные заметки, папки, состояние канбана, метаданные представлений) собираются в единый дельта-пакет только для измененных сущностей.
  - Текстовый батч сериализуется и сжимается (Gzip/Zstandard), после чего шифруется клиентом через AES-256-GCM с уникальным nonce и подписывается ключом устройства Ed25519.
  - Вложения (`.attachments/`) передаются отдельно по принципу Content-Addressed Storage (CAS) по их SHA-256/BLAKE3 хешам с автоматической дедупликацией.
- **Сверка состояния через Merkle Root**:
  - У каждого хранилища вычисляется корневой хеш `VaultStateHash`.
  - Сверка между устройствами происходит за 1 запрос: если хеши совпадают, синхронизация завершена; если нет — запрашивается только дифференциал.
- **Система доверенных устройств (Device Trust & Pairing)**:
  - Идентификатор устройства: `DeviceID = "slag-" + sha256(pubkey).slice(0, 8)`.
  - Варианты сопряжения:
    1. **QR-код**: быстрое сканирование экраном мобильного устройства.
    2. **6-значный PIN-код (Short Pairing Code)**: временный тикет (TTL 5 мин) для безопасного обмена ключами без камеры.
    3. **12 слов (BIP-39 Seed)**: детерминированное восстановление доступа к хранилищу и релею на чистом устройстве.
    4. **Локальная сеть (mDNS/LAN Discovery)**: сопряжение устройств в одном Wi-Fi в один клик.
- **Управление квотами и очисткой**:
  - Пакеты удаляются с сервера сразу после подтверждения доставки (`ACK`) от всех доверенных устройств либо по истечении TTL (7 дней).

### 14.3. Распределенный AI Lease
- Межплатформенная координация обработки заметок: заметки с мобильного устройства приходят со статусом `aiStatus: pending`, а стационарный ПК берет `lease` (блокировку на обработку), запускает классификацию и пушит обратно в синк обогащенные метаданные без повторной траты токенов.

### 14.4. Автоматические Git-коммиты
- Опциональная интеграция с локальным Git: фоновый тихий коммит версий при закрытии приложения или по расписанию (`auto-sync: YYYY-MM-DD HH:mm`).
