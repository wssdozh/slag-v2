# Дорожная карта SLAG v2 (ROADMAP)

## Видение продукта
SLAG v2 — ультраминималистичная, быстрая и полностью локал-фёрст система заметок, объединяющая строгую эстетику **Linear Dark**, эргономику потока **Telegram** и расширяемую структуру **Obsidian** (Markdown + YAML Frontmatter) с нулевым доверием к внешним серверам (Zero-Knowledge E2EE).

## Детализация Этапа 4: Сквозная E2EE-синхронизация

### 4.1. Сервер ретрансляции (Zero-Knowledge Relay Server)
- [x] Архитектурное проектирование: модель Non-Storage Relay (эфимерный FIFO почтовый ящик, отсутствие постоянной БД заметок).
- [ ] Разработка сервиса `slag-relay`:
  - WebSocket-комнаты по слепому `SyncRoomId = HMAC-SHA256(VaultKey, "room-v1")`.
  - Мгновенная ретрансляция пакетов подключенным онлайн-девайсам (latency < 30 мс).
  - Буферизация дельт для офлайн-устройств с TTL (7 дней) и моментальным удалением по `ACK`.
  - Эндпоинты для сопряжения устройств по 6-значному коду.
- [ ] Развертывание тестового инстанса на боевом VPS `netcup-server` (152.53.199.71:8320) с systemd автозапуском.
- [ ] Поддержка подключения пользовательских серверов (Self-hosted mode) в один клик.

### 4.2. Протокол пакетирования дельт (SyncBundle & Merkle State)
- [ ] Полный охват синхронизируемых данных:
  - **Заметки (Items)**: контент `.md`, YAML-метаданные, подзадачи, дедлайны, приоритеты.
  - **Папки (Folders)**: структура дерева, иконки, цвета, AI-описания, порядок сортировки.
  - **Виды и настройки (Workspace & Views)**: канбан-колонки, `statusMapping`, режимы ленты/фильтрации.
  - **Вложения (Attachments)**: content-addressed передача по BLAKE3/SHA-256 хешам с автоматической дедупликацией.
- [ ] Упаковка:
  - Формирование пакета дельт `SyncBundle` только для измененных сущностей.
  - Сжатие текстового батча через Gzip/Zstandard (уменьшение объема трафика в 3–5 раз).
  - Шифрование пакета на клиенте (AES-256-GCM / XChaCha20-Poly1305) с уникальным nonce.
  - Подпись пакета приватным ключом устройства (Ed25519).
- [ ] Мгновенная сверка состояния хранилища через корневой хеш `VaultStateHash` за 1 сетевой запрос.

### 4.3. Система доверенных устройств и сопряжение
- [ ] Идентификация устройства: `DeviceID = slag-<pubkey-hash>`.
- [ ] Сценарии сопряжения (на выбор пользователя):
  - **QR-код**: для сценария «ПК ➔ Телефон с камерой».
  - **6-значный пин (Short Pairing Code)**: безопасный обмен ключами по коду `XXX-XXX` (TTL 5 мин) с проверкой контрольных цифр SAS.
  - **12 слов (BIP-39 Mnemonic Seed)**: детерминированное восстановление хранилища и доступа на новом девайсе при утере остальных.
  - **Локальная сеть (mDNS/LAN Discovery)**: сопряжение девайсов в одном Wi-Fi в 1 клик.
- [ ] Белый список доверенных устройств (Device Trust List) с возможностью отзыва доступа.

### 4.4. Интерфейс управления (SettingsModal -> Синхронизация)
- [ ] Лаконичная вкладка в стиле Linear Dark.
- [ ] Карточка статуса соединения: онлайн/офлайн, задержка (ping), время последней синхронизации.
- [ ] Список подключенных устройств с индикаторами активности.
- [ ] Диалог добавления нового устройства с выбором метода (QR, 6-значный код, 12 слов).
- [ ] Переключатель «Официальный релей» / «Свой сервер» с валидацией URL.

## Детализация Этапа 5: Распределенный AI Lease
- Межплатформенное делегирование тяжелых задач ИИ.
- Заметки, созданные на телефоне на бегу, получают статус `aiStatus: pending`.
- Десктоп, подключенный к электросети и быстрому интернету, автоматически берет временный `aiLease` (блокировку), выполняет разбор (автотеги, раскладку по папкам) и пушит результат обратно в синк.
- Исключение двойных списаний API-токенов и сохранение заряда батареи смартфона.
